## 2. P0 问题（影响正确性/会崩溃，必须先修）

### P0-1 `process_bigger_situation` 空集崩溃，C++ 与 Python 双路径都挂

- **位置**：`utils/probability.py:884` `min_mine_cnt = min(mine_num)`；`cpp/mscore.cpp:1055` 同语义
- **触发**：`A(ck)` 枚举的所有组合都不满足 `min_val <= _mine_num + num10 <= self.a`，`mine_num` 为空
- **实测复现**：`a=1, num10=0` 时抛 `ValueError: min() arg is an empty sequence`；C++ 抛错后回退 Python，Python 抛同样错
- **后果**：不是优雅降级，是直接崩溃。触发场景 = 残局（雷大量被标记、内部未开格少）或设置里总雷数填错
- **改法**：`mine_num` 为空时返回"无有效方案"信号，上层转随机/提示分支

### P0-2 14 个模板是死模板，从未参与识别

- **位置**：`utils/vision.py:117-131`
- **事实**：25 个模板分两种尺寸——11 个 `(18,12)`、14 个 `(20,28)`；待匹配补丁 `(18,13)`。14 个大模板大于补丁，`cv.matchTemplate` 抛 `cv.error` 被 `except cv.error: pass` **静默吞掉**
- **后果**：程序一直只用 11 个模板工作；换分辨率时**不会有任何报错**，只会静默误识别
- **改法**：加载时校验模板尺寸兼容性，不兼容的显式告警

### P0-3 打分语义退化：`np.sum(响应图)` 把小模板匹配退化成单点比较

- **位置**：`utils/vision.py:122-123`
- **事实**：小模板 `(18,12)` vs 补丁 `(18,13)` 的响应图是 `1×2`（仅 2 个位置），`np.sum` 把"全位置最优匹配"变成"2 个固定对齐点求和"
- **实测印证**：模板贴回格子自测，**10 号（雷）被识别成 9**（11 样本错 1，准确率 90.9%）
- **改法**：模板统一到补丁尺寸；打分改 `np.min`；加置信度不足重扫护栏

### P0-4 耗时模型拟合 O(n²) 且未按注释截窗

- **位置**：`utils/probability.py:197-208`；注释称"只取最近 200 条（`rows[-200:]`）"，实际传**全量** `rows[:]`
- **实测**：1777 条样本时 `_ps_fit_k` = **520 ms**（全部）/ **1.5 ms**（最近 200 条），差 **300+ 倍**；3000 条时升到 1496 ms
- **后果**：**玩得越久越慢**（样本线性增长、拟合二次增长）
- **改法**：真正截窗到 200 条，或改增量拟合

### P0-5 测试用"两边一致"代替"两边都对"

- **位置**：`bench/compare_native.py` 全部断言
- **问题**：只验证 `C++ == Python`。**同一个错误在两边同时实现时，测试永远绿**
- **实测佐证**：我用独立暴力枚举（`bench/locate_prob_bug.py`）对 4×4 小棋盘做第三方判定，**项目概率计算正确**（3 个有区分度局面最大差 0.00000000）。这证明实现是对的，但也暴露：**仓库里没有这类独立判定**，全靠运气
- **改法**：补一个暴力/蒙特卡洛判定器作为独立参照，纳入 CI

## 7. 前沿算法调研（大情况是否该换算法）

参考 [A Phase Transition in Minesweeper (FUN 2020)](https://ar5iv.labs.arxiv.org/html/2008.04116)：

- 论文证明扫雷 INFERENCE 是 **co-NP-complete**，且在临界雷密度处出现**相变**——精确推理的难度在此处峰值，"算法屏障"确实存在
- **但对本项目的意义有限**：实测 `part_solve` 在真实局面上只要 2.3 ms，`win_rate` 0 ms。**当前根本不处在需要 SAT/CP-SAT 的难度区间**
- 专家局雷密度 99/480 ≈ 20.6%，低于相变的临界难度区间；项目现有"分组独立枚举 + 组合数加权"已是业界通行的精确方法
- **结论**：现阶段引入 SAT/MDD/神经网络是**过度工程**，收益远小于视觉与等待优化。若未来要提升胜率（而非速度），再考虑 MDD/SAT

这是我特意补的一节，直接回答你的第四问。

**可用的第三方证据（本报告已部分建立）**：

1. **暴力枚举参照**（`bench/locate_prob_bug.py`）：对 4×4 小棋盘穷举所有合法雷布局，用组合数学直接算每格概率，再与项目结果比。**与项目实现零共享代码**。已实测：3 个有区分度局面，最大差 `0.00000000` → 项目概率正确。
