## 0. 结论先行（先看这五条）

**① 你的目标（大情况快 10 倍）可以达成，但瓶颈不在算法。**

**③ 还差什么才能到 10x**

单步预计 487 → 约 194 ms（按新决策 79.8ms + 视觉 48ms 折算），约 **2.5x**。剩下的缺口全在两处：

**④ 发现并修复了一个比速度更严重的正确性缺陷（已用独立暴力枚举验证）**

## 2. 已修复的问题（本会话完成，均带验证）

### 修复 A：`_ps_refit_k` 未按承诺截窗（P0，已修）`9d51cdf`

- **问题**：注释称「只取最近 200 条」，实际传全量 `rows[:]`，O(n²)
- **实测**：1777 条时 25.5 ms / 最近 200 条 1.66 ms（**15.4x**）；3000 条时升至 1.5 s
- **修复**：真正截窗（`_PS_FIT_WINDOW=200`）
- **效果**：`_ps_observe` **39.8 → 19.8 ms**，`_ps_refit_k` **49.2 → 5.6 ms**

### 修复 B：`pbs` 空集崩溃（P0，已修）`9d51cdf`

- **问题**：`min(mine_num)` 在无可行雷数组合时抛 `ValueError`；C++ 与 Python **双路径都崩**
- **实测复现**：`a=1/num10=0` 时崩溃
- **修复**：退到均匀先验（`p_mine = clamp((a-num10)/未开格, 0, 1)`），C++ 同步实现并重编
- **验证**：崩溃用例现均正常返回

### 修复 C：跨线程共享 `Solver.img`（P0，已修）`9d51cdf`

- **问题**：`main.py` 在 `help_thread.start()` 之后，又于 GUI 线程调用同一 Solver 的 `complete_scan`，而该方法会写共享 `self.img` → 两线程交叉写，后台可能拿到错帧截图
- **修复**：GUI 改用独立一次性扫描器 `_gui_scan_once`，不触碰工作线程状态

### 修复 D：样本文件无限增长（P1，已修）`9d51cdf`

- **问题**：`data_time.json` 只增不减，每次全量重写
- **修复**：滑窗上限 `_PS_SAMPLES_KEEP=1200`，写成本有上界

### 修复 E：近似分支的组间独立性假设错误（P0 正确性，已修）`facb976`

这是本次最重要的发现。

- **问题**：`process_bigger_situation` 的近似分支（`total>10000`）对每组独立归一化，丢掉了总雷数这个跨组耦合约束。正确权重应是
  `W(m_1..m_G) = ∏H_g(m_g) · C(U, R−Σm_g)`，旧公式缺失 `C(U,R−Σm)` 项
- **实测影响**（独立构造，非复用项目代码）：

  | 构造 | 旧近似误差 |
  |---|---:|
  | 双组对称 | **46.67 pp** |
  | 偏斜分布 | **100.00 pp** |
  | 三组混合 | **75.00 pp** |
  | 单组 | 0.00 pp |

- **修复**：改用生成函数 DP（雷数直方图 `H_g` + 卷积 `T(t)` + 组合数加权）
- **验证**：生产两条路径（Python `_pbs_compute_dp` 与 C++ `pbs_compute`）均与暴力枚举对拍，**最大差 0**；`compare_native.py` ALL CONSISTENT
- **说明**：单组时误差为 0 —— 这就是为什么该缺陷长期未被发现；只在多组大局面暴露

## 7. 前沿算法调研（大情况是否该换算法）

参考 [A Phase Transition in Minesweeper (FUN 2020)](https://ar5iv.labs.arxiv.org/html/2008.04116)：

- 论文证明扫雷 INFERENCE 是 **co-NP-complete**，且在临界雷密度处出现**相变**——精确推理的难度在此处峰值，"算法屏障"确实存在
- **但对本项目的意义有限**：实测 `part_solve` 在真实局面上只要 2.3 ms，`win_rate` 0 ms。**当前根本不处在需要 SAT/CP-SAT 的难度区间**
- 专家局雷密度 99/480 ≈ 20.6%，低于相变的临界难度区间；项目现有"分组独立枚举 + 组合数加权"已是业界通行的精确方法
- **结论**：现阶段引入 SAT/MDD/神经网络是**过度工程**，收益远小于视觉与等待优化。若未来要提升胜率（而非速度），再考虑 MDD/SAT
