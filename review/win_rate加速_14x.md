**win_rate 微基准总耗时 4652.15 ms → 329.49 ms，加速 14.12x。**
全部 33 个用例**输出指纹逐位一致**（MD5 校验和相同），目标 10 倍已达成。

| 指标 | 改前 (MD5) | 改后 | 加速 |

## 一、瓶颈定位（靠测量，不靠猜）

基线：33 个生产真实决策点，最重用例 #13 只有 **6 个世界**却耗时 **2246 ms**（42.4 万递归节点）。
⇒ 瓶颈不在世界数，在**每节点固定开销**。

热度统计（`MSW_WR_STATS=1`）显示 case 13：
```
hash_calls=424114  hit=221282  miss=202832  hit_rate=52.2%  entries=62455
lookup_ms=136.50  insert_ms=23.49
```
每次递归都要：
1. 把棋盘归一化成 **2304 字节**缓冲区（分配）
2. 对 2304 字节算 **MD5**
3. 输出 16 字节 `std::string` 作为 memo 键

⇒ **哈希是压倒性瓶颈**。

## 二、方案演进（含两次失败，务必读）

### 方案 A：无分配 128 位哈希 → **4.66x**

- 零分配、单遍内联，归一化融进循环（不再建 2304B 缓冲区）
- 总耗时 4803.7 → 998.3 ms
- **但仍每节点扫整盘 576 格**

### 方案 B（错误，已修正）：位置感知「可加」哈希想做到 O(1)

关键观察：递归时子棋盘只在**一个格**上与父棋盘不同
（`wr_f` 里 `nb[v*W2+u] = c10`），所以哈希可以增量更新。

**但我第一版把 `cell_mix` 写成了顺序混合**：
```cpp
h1 += ...;
h1 ^= h1 >> 31;      // ← 不可逆！
```
`xor-shift` 不可逆 ⇒ 无法用"减去旧值"撤销 ⇒ **增量算出的键与全盘哈希不一致**
⇒ 同一棋盘产生两个键 ⇒ memo 命中率崩塌：
```
hash_calls 42.4万 → 145万      entries 6.2万 → 22.7万
```
耗时反而劣化（376 ms → 1299 ms）。

**修正为纯可加**（`H = Σ_i f(i, v_i)`，累加器只做加法）后恢复正确，
并写成**不变式测试**逐位证明。

### 方案 C（用户建议其一，失败）：把打包值当 **memo 键**

实现了 `PackedBoard`（36 个 uint64 = 2304 位，无碰撞），**但性能崩溃**：
```
总耗时 380 ms → 424348 ms（劣化 1000 倍）
case 13: 245 ms → 422202 ms（劣化 1700 倍）
```

**根因（重要教训）**：`PackedBoard` 用 `std::array<uint64_t, 64>` 固定大小，
**每个键是 ~512 字节**。`unordered_map` 的 `find`/`insert` 需要复制整键
⇒ 比算 MD5 还贵。

**教训：打包表示适合「存棋盘」，不适合「当 memo 键」。键必须小。**

### 方案 D（用户建议其二，成功）：把 **`Board` 本身**打包化

用户建议："用长整数表示整个棋盘，每 4 位存一个格子的信息，因为格子信息不超过 16 种"。

把 `using Board = std::vector<int32_t>`（2304 B，堆分配）改成
**打包类**（`std::array<uint64_t, 36>` = 288 B，可栈上分配）：

```cpp
class Board {
    inline int32_t get(size_t pos) const;   // 取 word + 位移
    inline void    set(size_t pos, v);      // 清 4 位 + 写 4 位
    // operator[] 返回 Ref（可读可写）⇒ 调用方 `b[pos]` 无需改动
    std::array<uint64_t, NW> w_;
};
```

**收益**：
- **拷贝 2304B → 288B（8 倍压缩）**：`Board nb = b` 是 wr_f 最高频操作
- 小到可**栈上分配、无堆 malloc**
- `cell_around` 邻域取值走位运算，缓存友好

**结果**：380.47 ms → **329.49 ms**（12.23x → **14.12x**）。

## 三、最终方案

**两层优化叠加**：

| 层 | 优化 | 收益 |
|---|---|---|
| 存储层 | `Board` 打包（4 位/格，288B） | 拷贝/分配成本 ↓8 倍 |
| 键层 | 纯可加 128 位**增量**哈希（16B，递归时 O(1) 更新） | 免整盘扫、免 MD5 |

| 版本 | 总耗时 | 加速 |
|---|---:|---:|
| MD5 + `vector<int32_t>`（原实现） | 4652.15 ms | 1.0x |
| 无分配 128 位哈希 | 998.3 ms | 4.66x |
| 纯可加增量哈希 | 380.47 ms | 12.23x |
| **+ Board 打包化（当前）** | **329.49 ms** | **14.12x** |
| 打包当键（失败） | 424348 ms | 0.01x |

## 五、诚实边界

1. **14.12x 是微基准（33 个固定决策点）数字**。
   端到端整局耗时受视觉扫描/点击等非算法段影响，
   **整局加速比会明显低于 14.12x**（本次端到端只测到 p90 12.5s→9.8s，约 1.28x）。
2. **未测 2000 局**的胜率与总耗时变化。
3. `Board` 容量上限 `PACK_MAX_CELLS = 1024`（64 words），超限抛异常。
   当前盘面 576 格，余量充足；**大盘面需调大**该常量。
4. `MSW_WR_STATS` 统计是**诊断探针**（默认关闭），不参与生产路径。
5. **未做** `Board` 打包化后 `cell_around` 的独立微优化
   （邻域 9 格可合并为 word 级批量取值，理论还有空间）。
