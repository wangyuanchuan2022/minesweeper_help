# 扫雷助手：全部实验与结论审计

日期：2026-11-04。审计对象：当前工作区中 `review/`、`docs/`、`HANDOFF.md` 所载实验与结论，以及可追溯的 `bench/`、`sim/`、`state/ab/`、`bench/data/` 证据。当前 HEAD 为 `84fa7ce`，但大量数据、脚本与报告未提交；本报告审的是工作区快照，不是单一提交。

## 总结论

项目的自我纠错意识较强：模拟器规则、flood、枚举器、采样线程、参数接线、残局归属等多处仪器错误被发现并撤回，许多最新报告也已主动收窄结论。**但并非“改完即全部可信”**：当前权重优化线的实验身份与独立性尚未成立，角落开局的效果仍未确认，部分性能/前瞻/视觉结论存在过度外推，若直接据此调生产参数或宣称胜率提升，依据不足。两席位审计还证实（组织者已抽查代码核实）：F/regret 评估器饱和后只取最大权重单终端分支，q 与 F 同在这一被截断分支上计算（同源同污染）；真实数据上 20% 的成功点为多终端，被丢弃概率质量中位 81.5%，且多终端集中在复杂局面、与权重优化目标高度相关——mm_full/merged_regret/LOO 现值须标记待重算。

优先级最高的改进不是再跑更多局，而是：**先修复 F/regret 评估器的单分支截断与 q/F 状态错配（P0-3），再补齐决策点的 `(seed, decision_id)` 身份与版本清单，重建发现/验证/分组交叉验证，最后才谈扩样。**

## 主要发现（P0 = 会使结论或采纳链失效；P1 = 显著削弱；P2 = 局部改进）

### P0-1：F 矩阵/regret 的样本身份、去重和独立性不成立

**事实与重算：** `bench/collect_midgame_cases.py:122-134` 的快照不含 `seed/game_id/step`；`bench/dump_metric_matrix_ext.py:72-76` 与 `bench/merge_and_eval_cases.py:65-72` 的去重键也没有这些身份，且不含完整 `cell_value/groups/ck`。本次读取三批 2286 条原始快照，按当前键有 51 组重复，其中 18 组的完整棋盘或约束不同；例如 `midgame_cases.json` 第 164 项与 `midgame_cases_ext.json` 第 288 项同键但 `cell_value` 不同。三批数据混在同一键空间；复席位实测 51 组重复键中 16 组跨文件（含发现集↔冻结验证集 ext2），且 `bench/merge_and_eval_cases.py:65-72` 的 `merged[case_key(c)] = c` 对同键静默覆盖。统计席进一步定量：**ext2（预注册验证集）456 点中 80 点（17.54%）的 case_key 与 discovery 重复，其中 16 组棋盘完全相同**——与 `review/P1预注册_发现验证集冻结.md:27-33` 的独立性声明直接冲突，验证集独立性已被实际破坏而非仅属理论风险。

**影响：** `mm_full.json` 的 287 点和 `merged_regret.json` 的 300 点不能自动视作 287/300 个独立观测；LOO 的逐点留出、发现/验证“真正独立”的说法、配对 p 值和 MDE 都缺乏可审计分母。已有 `optimize_weights.json` 的 LOO 只能作为探索，不可作为生产采纳依据。严重度需分两层说清（实验会话复核的合理细化）：**已证实**的是同键不同内容被静默合并（丢数据/串数据）与身份缺失导致无法做按局分组验证；**未观察到**的是本批数据存在同棋盘多决策点泄漏进训练折——按 `(w,h,a,cell_value)` 对 1509 个去重 case 分组，同棋盘多点组为 0，mm_full 的 287 个 ok 点中属重复键组的也为 0。因此结论是“验证能力缺失 + 数据合并缺陷”，不是“LOO 已被证实泄漏”。统计席独立机检精确复现 51 组/18 组（组织者口径），实验会话用完整字段集分组得 41 组/14 组——差异来自分组字段定义，不影响上述定性结论。

**改进：** 在采集时写入 `seed, game_id, decision_id/step, source_batch, board_view_hash, solver_config_hash`；以完整观测和约束做内容哈希，禁止只按候选坐标去重。按 `game_id` 做 GroupKFold/leave-one-game-out，并按局划分发现/验证，所有折内重新拟合与选模型。修复前不扩样、不冻结权重、不运行“只一次”的验证集。

外部依据：[scikit-learn 交叉验证指南](https://scikit-learn.org/stable/modules/cross_validation.html)明确建议组结构数据使用 group-wise CV；[nestedcv 指南](https://rdrr.io/cran/nestedcv/f/inst/doc/nestedcv.Rmd)说明特征/参数选择必须留在训练折内，否则性能估计有偏。

### P0-2：角落开局没有满足采纳证据，配对复核链也不完整

**事实：** `review/P2预注册_角落开局.md:40-45` 要求 McNemar 显著且效应达到 MDE；正式轮 +3.25pp、p=0.0154，未达原 MDE。独立复现 +1.10pp、p=0.4389，按预注册只能称方向一致，不能称稳定正收益。`review/P2结论_角落开局两轮.md:38-50` 的“尚未确认稳定正收益/未达 40%”是正确收窄。

**缺陷：** `bench/ab_first_click_corner.py:268-325` 最终 JSON 只保存汇总，未保存逐局 `won`、双方独赢数或配对 CI；`p2_replication_verdict.json` 的 `mcnemar` 也是 `null`。预注册要求的“配对 95%CI”没有结构化交付，无法只靠最终结果独立复核（统计席复算与实验会话从日志重算一致：正式 Δ=3.25pp、95%CI [+0.66,+5.84]pp；复现 Δ=1.10pp、95%CI [−1.56,+3.76]pp；两轮幅度差 z=1.136、p=0.256，支持“两轮不可区分”）。统计席并发现正确配对 MDE(80%) 应为 3.70/3.80pp，而非预注册所写的 4.26pp——原公式低估门限约 0.5pp，正式轮 3.25pp 在正确门限下同样不达标，判定（DIRECTION_ONLY）不变。

**机制指标：** 理论角落首格零率为 `C(476,99)/C(479,99)=49.8463%`。复现 955/2000=47.75%，稳定重算精确二项双侧 p=0.0634（正式 49.20% 的双侧 p=0.5762）。所以 `review/P2结论_角落开局两轮.md:21-23` 的“两轮与理论一致⇒机制可靠”过强；应写“复现轮有边缘性偏差，未足以否定理论，需排查 RNG 与记录保真度”，不能宣称机制已证伪。

**改进：** 保存每臂每 seed 的结果、first_num、配置与二进制哈希，直接从明细生成 McNemar 和配对 CI（统计席评估：补齐需重跑 2×2000 局 ≈ 2×35min，日志只有进度行不可重建）。首点收益尚未确认，不建议当前据此改生产；若仍保留候选，须事前固定一个比较和全新 seed，按配对不一致比例做功效设计，不以“方向一致”作为有效证明。

### P0-3：F/regret 评估器只保留单个最大权重终端分支，q 与 F 状态不同源

**事实（复席位发现，组织者抽查代码证实）：** `bench/dump_metric_matrix_ext.py:302-303` 对世界集 `saturate` 后过滤出非胜、有候选的终端；`:316-317` 以 `terms.sort(key=lambda t: -t[2])` 只取最大权重单分支计算 F；而 q 由 C++ `exact_eval`（`:320-327`）自行饱和评估（复席位对照 `cpp/mscore.cpp:1980-1999` 为全终端加权）。受控 6×2 用例产生 4 个合法终端（权重 4/9、2/9、2/9、1/9），现有实现只保留 4/9，静默丢弃 5/9 概率质量。

**影响：** `mm_discovery`（77 点）、`mm_full`（287 点）、`merged_regret`（300 点）、F 矩阵、子集与 LOO 的输入不是所声称条件下的完整递归值；偏差方向未知，不能外推为生产求解器有错。**修复重算前，这些数值不得引用为终值**（含 HANDOFF 中的连续/分层权重与最佳 LOO 读数）。实验会话对真实 mm_full 前 60 个 ok 点复算：20%（12 点）存在多终端态（最多 192 个），丢弃概率质量中位 81.5%、均值 76.8%、最大 98.6%——危害比构造用例更严重；且多终端集中在复杂局面，与权重优化的目标变量高度相关，不能假定偏差随机可忽略。

**口径更正（2026-11-04 19:52，两席位与实验会话三方一致，组织者此前表述有误）：** `dump_metric_matrix_ext.py:322` 传给 `exact_eval` 的 `worlds` 正是 `wk2`（terms[0] 子世界集）——**q 与 F 同源，同在截断分支上计算**；早期稿“q 从原状态独立饱和、与 F 不同源”不成立，真正问题只是单分支截断。

**改进：** 统一状态转移接口：一次饱和得到带权终端列表，对每个终端分别算 F 与 q 后按权重聚合 regret，不得先聚合标量 V* 再挑分支；q 与 F 必须传同一 `(world_subset, opened)`；C++ 侧增加饱和终端导出或接受该状态，禁止自行另选终端；任一候选/终端 Budget 整点标未覆盖。最小验证：6×2 用例须保留 4 终端且权重守恒，注入“只留最大分支”变异必须报红。

### P1-1：MDE 公式与配对设计不匹配，且多处把 MDE 当 CI/排除界限

`bench/ab_first_click_corner.py:96-100` 和 `review/P2预注册_角落开局.md:63-80` 用 `sqrt(2p(1-p)/N)`，这是独立两样本的粗略形式，不含配对不一致比例。配对 McNemar 的功效取决于 discordant proportion：统计席按配对口径重算，正确 MDE(80%) 为 3.70/3.80pp，预注册所写 4.26pp 偏高，且不能据此声称“不显著即可排除 ≥4.2pp”。`review/中局前瞻与贪心破平局评估.md:48-53` 的“小于约 5pp 都测不出来”同样过于绝对。

**改进：** 报告效应差及其 CI，功效单独按配对模型/仿真计算；MDE 仅用于设计，不用于事后把效应划成“存在/不存在”。`review/2000局胜率结果.md:17-18` 的“C++ 加速没有影响胜率”应改为“未检出胜率变化”；历史 107/316 与当前 709/2000 的非配对描述性差为 +1.59pp，近似 95%CI [-4.03,+7.21]pp，且代码/配置可能不同，不能证明等效。

### P1-2：前瞻与手工指标仍有多重比较、符号检验和外推问题

- `review/中局前瞻与贪心破平局评估.md:179-184` 把 3-ply 的 11 优/7 劣、p=0.481 与平均 regret 从 0.0177 降至 0.0071 并列。符号检验忽略差值幅度，不能据此否定均值差；均值差也不能在无 CI、无局级聚类、多重比较未校正时直接宣布有效。应给按 `game_id` 聚类的配对差 CI，并预先指定主比较。
- 同文 `:45-46` 的“真实有效准则不应换 seed 后反向”作为判据不成立；小效应在噪声下可反向。但统计席补了定量：两轮差 7.75pp、z=2.051、p=0.0402——“两轮不一致”本身统计可检出，报告可据此写“未确认稳定”，而不是拿方向必须永远一致当公理。
- 同文 `:254-265` 的“8 指标都不成立⇒不应调权重”与 `:352-362` 的“线性 prior 只能在单臂选格间插值”过强：不同线性组合可以选出各单臂都未选中的格，单臂不显著不排除组合有效。真正阻碍当前权重线的是 P0-1 的身份/独立性和自选择，而非数学上已证伪。
- `review/算法更新评估.md:21-32` 以 1/11 的局部分歧外推“中盘只能改变约 9% 决策/不能期待大幅提升”不成立；`review/算法选格对比与枚举器修复.md:9-11` 已纠正安全格的免费信息优势，旧的“safety=1 未必是好点击”不应再用于决策价值解释（时间成本须另算）。

### P1-3：样本选择与覆盖分类仍未闭合

`mm_full.json` 当前为 287/462 成功、175 err；`merged_regret.json` 为 300/462 成功、162 cpp_fail（这些数值同时受 P0-3 评估器缺陷影响，修复后须重算）。实验会话跑完 P1-c 全样本分类（`state/ab/p1_coverage.json`）：ok 186/462=40.3%、time_cap 259（56.1%）、err 17（3.7%）、node_cap 0，未覆盖率 59.7%；自选择偏差定量——ok 中位 worlds 106 vs 非 ok 1980（18.7 倍）。失败原因语义不同却被合并记为 `err`：F 矩阵 175 个 skip 中约 23 点是 `no_terms`（局面无可达终局，本质不可修复，worlds 中位仅 12），约 150 点是 `exact_eval` node_cap 超限（可修复）——应拆分标签，不能同记 `err`。成功点 limitation 约 8–26，而真实中位约 61，明显不能代表中局主力。

`review/regret评估原理与口径边界.md:148-166` 对此边界写得基本正确；但 `F矩阵说明与口径边界.md` 和 HANDOFF 仍将扩样写成进行中，不能把文件已生成当实验已完成。任何保留点上的 q 只代表“当前等权世界模型、当前候选集、完整递归成功”的代理，不代表真实全局胜率。

**改进：** 报告完整 CONSORT 式流程：原始点→去重→world cap→node/time cap→错误→最终点，分层列出保留率；失败不删除而标未覆盖。若要评估生产全分布，采用可完成的近似并单独校准，或对复杂度做加权/分层抽样，不能只分析易算点。

### P1-4：Arbiter 规则结论可保留，旧报告与外部比较需清理

外部官方帮助明确：首击后才布雷，首击格上的雷被移到随机空格，并未承诺 3×3 安全（[Arbiter 帮助](https://raw.githubusercontent.com/putianyi889/Arbiter-help/master/README.md)）。`sim/minesweeper_sim.py:107-132` 只排除首格的实现方向正确。

但 `review/算法域最终交付.md:72-85,115-120,169-176,184-187` 仍写“首点 3×3 与 Arbiter 行为等价/安全区通常更大/算法上限/真实与离线差就是视觉执行损耗”，已被后续修正推翻，不能继续引用。所谓“离线胜率”只是算法台架成绩，不是理论上限；真实与离线差还含棋盘 RNG、规则、配置和样本差异。

Couëtoux 原文只保证首击格安全，并明确其他版本才保证邻域为零（`review/_paper_couetoux.txt:3869-3874`），因此它的首点规则与本项目更接近；但其算法、采样与预算仍不同，34%/38.7% 只能作弱参照，不是上界。

[MinesweeperHQ](https://minesweeperhq.com/minesweeper-odds/) 的现代规则模拟明确把 50.7% 称为 strong baseline, not a ceiling；`review/胜率50%目标_可行性与路径.md:140-143` 的“算法已接近该口径上限”应改为“接近另一实现的强基线”。该资料也表明现代 3×3 规则下中心优于角落，不能反套到 Arbiter。

### P1-5：性能结论有真实微基准价值，但若干表述超出证据

`sim/first_click_rules.py:9-12` 的注释仍把“首格及 8 邻域安全”写成 Arbiter 常规做法，与当前模型和官方文档冲突；该脚本只能代表 `safe3x3` 变体，不能当 Arbiter 基线。

`review/论文研读_随机搜索与MCTS扫雷.md:35-63` 对 Bergstra 的使用越界：[原论文](https://jmlr.csail.mit.edu/papers/v13/bergstra12a.html)支持随机搜索作为自适应优化的比较基线，不支持“所以不应使用贝叶斯优化”，也不支持“不同数据集重要参数不同⇒本项目应按 limitation 分桶”。分层是可检验假设，不是论文证明的既有事实。论文关于网格与随机试验的比较也不意味着“每档只测一次”必然误导；真正的问题是每档噪声、预算公平和独立验证。

在线拟合 `k≈1.08–1.11` 及 `t(L)=base·k^(L-33)` 只适用于特定机器、二进制和负载下的启发式预算，不是普遍算法复杂度常数。`utils/probability.py:176-198,264-315` 的最近 200 条窗口、配对比值中位数与夹限能控制开销和异常值，但没有给出留出误差、预测区间或负载分层。`_ps_fit_k` 对窗口内样本做两两配对比值，没有按时间或负载条件配对；`ps_base_ms` 与 `ps_k` 又在同批样本上交替更新，因此可能混入近期负载与局面形状效应。应报告滚动时间外验证的绝对/相对误差及超预算率；窗口修复只证明开销下降，不证明预测准确。

`review/win_rate加速_14x.md` 已正确区分 33 点微基准 14.12x 与整局约 1.28x；统计席补充重算：**同一份数据三种口径差 2.4 倍**——加总 14.12x / 逐用例比值中位 8.76x / 中位耗时比 5.97x，且 case13 一个用例独占 before 总时长的 48.3%（剔除后逐用例中位 20.49x）。“目标 10x 已达成”的说法依赖最有利的加总口径，应三口径并列并标注单点支配。后续发现的同进程漂移进一步要求只采用独立进程或随机交替的新测量，不能用旧同进程耗时排序。

`review/算法性能评估与优化方案.md:11-17` 的“win_rate 唯一大头/part_solve 伪优化”只适用于 33 个固定决策点，不能外推整个程序；`review/主报告.md:21-23` 的“瓶颈不在算法/继续优化完全无效”同样只针对特定单步路径。`review/算法性能评估与优化方案.md:156-157` 以 120 局 33.3% 接近历史 33.86% 就称“台架可信”证据不足，只能称量级相符。

当前二进制 SHA256 与 P2 文档一致，但工作区有大量未提交脚本/数据，单个哈希不足以复现全部结果。应为每次运行保存 Git HEAD、dirty diff/脚本哈希、Python/依赖、完整 CLI、输入数据哈希、二进制哈希和环境负载说明。

### P1-6：视觉/OCR 与 UI 的真实泛化仍未验证

`review/视觉域.md:257-263,478-489` 已诚实承认无真实屏幕标注集，这是正确边界；因此 1px 翻转、模板退化、合成噪声分离和 22x 加速可作受控证据，不能等同真实识别准确率提升。优先补不同 DPI、主题、缩放、遮挡和重绘状态的 `_grab_board + cell_value` 黄金集，报告逐格混淆矩阵与整盘完全正确率，不能只报速度。

`review/UI视觉优化.md` 的对比度与几何实测有可取之处，但 offscreen 像素、颜色声明和真实交互是不同证据层。[WCAG 2.2 SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)以声明前景/背景色的相对亮度计算为主，正常文本 4.5:1、较大文本 3:1，并明确禁用控件有例外；ΔE≈16 不是“红绿色盲不可分”的普遍阈值。应按角色分别报“声明色对比度”“实际截图像素”“真实可读性”，并补非颜色编码（数值/纹理/形状）。

### P1-7：实验批异常局静默缩小胜率分母；计时协议不查子进程退出码

- `sim/eval_harness.py:407-411` 异常局返回带 `error` 的记录，`:555-559` 把它们排除出胜率分母（`n = len(ok)`）；`bench/ab_policy.py:449-454` 同一模式。历史通用胜率、早期首点合并与 B 线完成数不是请求样本的完整结果，不能与 P2 新版完整门禁（`bench/ab_first_click_corner.py:121-145` 已修复该问题）等价比较。
- `bench/timing_protocol.py:92-93` 只要 stderr 出现 `__ELAPSED__` 就把计时入选，不检查 returncode——失败子进程可贡献“看似有效”的计时；`bench/bench_wr_speed.py（已随 win_rate API 删除）:70-85` 只检查用例交集不做集合相等。14.12x 在按新进程协议复测并补 returncode/集合硬门前，不应作为可复现性能结论引用。

**改进：** 按请求 seed 建完整配对键，异常单列未覆盖，非完整禁止出正式胜率与 p 值；计时/速度基准加 returncode、输出格式与用例集合硬门，每配置独立进程并保存失败项。最小验证：连续 3 个 seed 中第 2 个异常时输出必须 requested=3/completed=2/complete=false；注入 exit 3 且带 `__ELAPSED__` 的子进程必须整项判不可靠。

## 推荐整改顺序

1. **冻结权重验证，不读取 ext2 结果**：补 `(seed, game_id, decision_id)`、完整内容哈希与运行 manifest，重新生成数据。
2. **建立统一实验账本**：每实验登记假设、主终点、采样单元、配置/输入/代码哈希、排除原因、主分析和有效状态；历史文档标撤回。
3. **统计层**：局级配对/聚类 CI，必要时嵌套或 Group CV；发现/验证按局隔离，多重比较预注册主终点，MDE 仅作设计工具。
4. **角落开局**：保存原始明细并复核配对分析；在确认前不改生产、不把方向一致写成稳定收益。
5. **覆盖与真值**：完成全 462 点分类，报告易算子集边界；为 V* 增加小而可穷举、可手算且能终止的已知答案用例，区分引擎一致性与真实最优性。
6. **性能**：沿用独立进程/随机交替计时，保留“微基准≠整局”的双口径，先修同进程漂移根因或持续隔离它。
7. **真实端验证**：OCR 建黄金标注集，UI 分声明色/实际渲染/真实交互三层验收，最后用真机回放或受控真机 A/B 验证离线收益能否兑现。
8. **耗时模型**：按时间顺序做留出验证，报告误差分布、超预算率与负载分层；不要把拟合 `k` 当普遍常数。
