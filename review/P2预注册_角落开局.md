## 一、假设

**H1（中间指标，机制验证）**：角落开局的「首格数字 = 0」比率显著高于中心开局。
- 理论预测（精确组合数学，Arbiter 规则，N=479, a=99）：
  角落 **49.85%**，中心 **15.45%**。
- 这一条**不是**要检验"哪个更好"，而是**验证实现与组合学推导一致**。
  若实测角落 0 率没有显著高于中心 ⇒ 先查仪器，不进入 H2。

**H2（最终判据）**：角落开局的整局胜率高于中心开局。
- 这是**唯一**的"是否采纳"判据。

## 三、判据（跑之前定死）

### 主判据（H2，决定是否采纳）
- **整局胜率**，配对 McNemar 精确检验（双侧），α = 0.05
- 报告：两臂胜率、Δ、配对 95%CI、双方独赢数、MDE(80%)
- **采纳条件**（两条必须同时满足）：
  1. McNemar p < 0.05 且 Δ > 0
  2. 效应量 ≥ MDE（即本样本有能力检出该效应）

### 副判据（H1，机制验证，不决定采纳）
- **首格数字 = 0 的比率**，两臂各自 Wilson 95%CI
- 与理论值（49.85% / 15.45%）对照
- **若 H1 不成立**（角落 0 率未显著高于中心）：
  暂停 H2 的解读，先查仪器（记录点、坐标、延迟布雷时机）

### 必须分开报的两个指标（禁止混淆）
| 指标 | 性质 | 用途 |
|---|---|---|
| 首格为 0 率 | **中间指标** | 验证机制生效 |
| 整局胜率 | **最终判据** | 决定是否采纳 |

**明确规定**：即使 H1 大幅改善而 H2 不显著，**也不得**声称"角落开局有效"。

## 四、样本量 N 的预设（按目标 MDE 反推）

基线胜率 p ≈ 0.335（本项目实测 33.50%~35.25%）。
配对比较 MDE(80%, 双侧 5%) ≈ (1.96 + 0.84) × sqrt(2p(1-p)/N)。

| N | MDE(80%) 近似 | 说明 |
|---:|---:|---|
| 400 | 9.5pp | 只能检出很大的效应 |
| 1000 | 6.0pp | |
| **2000** | **4.2pp** | **主选：与文献 MCTS 的 +4.7pp 量级匹配** |
| 4000 | 3.0pp | 若要检出 3pp |
| 8000 | 2.1pp | 若要检出 2pp |

**冻结决定：N = 2000/臂（共 4000 局）。**

理由：文献 Couëtoux 的 MCTS 相对 CSP 提升约 +4.7pp（仅作量级参考，
不是上界）。若角落开局有同等量级效应，N=2000 有 80% 功效检出。
N=2000 若仍不显著，只能排除 ≥4.2pp 的效应，**不能**排除更小的效应。

**停点规则**：跑到 N=2000 即停，**不看中间结果提前停**。
（中途不看 = 避免 optional stopping 导致 p 值失效。）

## 五、已知局限（必须随结果一起报告）

1. **延迟布雷下首点不同 ⇒ 棋盘不同**（布雷池在首点之后生成）。
   所以这是**策略级配对**（seed 作区组），不是"同一棋盘上选不同格"的配对。
   - **能回答**：一直点角落 vs 一直点中心，哪个整体更好
   - **不能回答**：同一棋盘上角落比中心好多少
2. **耗时读数不可用**（同进程漂移 2.4~5.4x，见
   `bench/report_repeat_slowdown.py`）。只报胜率与中间指标。
3. **绝对胜率不可与真机比较**（离线模拟视觉 100% 正确、无点击延迟）。
4. 若 H2 不显著，**不等于**"角落开局无效"，只等于"未检出 ≥MDE 的效应"。

## 六、启动前已完成的 sanity check（必须记录）

`first_num` 字段是 P2 的中间指标，新增后必须确认它**只增加观测、
不改变默认中心开局的决策行为**。实测（seed 20261102+，15 局）：

| 项 | 结果 |
|---|---|
| 与历史基线 `arm_baseline.json` 逐局对比（won/opened/steps） | **15/15 完全一致** |
| `first_num` 有值率 | 15/15 |
| 中心开局首格为 0 的比率 | 2/15 = 13.3%（理论 15.45%，量级吻合） |

**踩坑留痕**：第一版写成 `_view0[fy][fx]`，而 `BoardView` 只支持
`_view0.cells[y][x]` ⇒ TypeError 被 `except` 吞成 `None`，
导致 20 局全部 `first_num=None` 且**不报错**。已修正。
教训：`except Exception: x=None` 会静默吞掉字段访问错误。
