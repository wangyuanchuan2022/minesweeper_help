# 扫雷助手 UI 原型规范：简约现代、状态可信、证据可读

- 文档状态：HTML 原型实现规范（只读分析，不修改现有 Qt 源码）
- 设计目标：让用户随时知道“程序正在做什么、为什么这样建议、现在能做什么”。
- 框架判定：现有应用为 PyQt5（`ui/window.py:11`）；`package.json:1` 为空对象，后续 HTML 原型不预设 React/Vue 等框架。
- 证据基线：`review/全面审查-UI与调用流程-20261106.md` 与当前 `ui/window.ui`、`ui/window.py`、`main.py`；设计字段为原型契约，不代表后端已经提供。

## 1. 美学方向与简约现代原则

**方向：冷静的工具台，而非游戏皮肤。** 用冷灰背景、白色工作面、墨黑文字和单点青蓝强调建立清晰层级；热力色只留在棋盘内。去除摄影背景、半透明磨砂叠层和楷体/宋体混排，现有背景图与多种透明卡片见 `ui/window.py:71-76`、`ui/window.py:222-225`、`ui/window.py:305-318`。

1. **状态先于装饰**：首屏第一视觉锚点是状态与主操作，不是背景图；现有界面只靠“计算中%”表达进度，证据见 `ui/window.py:578-580`。
2. **一屏一个主任务**：自动运行关注“运行—暂停—理解当前决策”，帮助模式关注“扫描—选格—理解依据”；保留现有三页分工，但改为任务导向命名，依据 `ui/window.py:228-232`、`ui/window.py:288-303`、`ui/window.py:371-390`。
3. **证据与动作相邻**：建议格、数值类型、推理依据和操作按钮同卡呈现，避免当前只能从格子弹窗阅读长文本，依据 `main.py:621-640`、`main.py:782-800`。
4. **确定性分级**：已证明、概率估计、未知识别必须视觉分轨；绝不把启发式胜率写成安全概率，现有统一文案风险见 `main.py:769-780`，审查结论见 `review/全面审查-UI与调用流程-20261106.md:364-391`。
5. **色彩不独立承担语义**：所有风险、推荐和状态同时有文字或形状；现有红绿底、蓝/黄/紫框叠加见 `main.py:642-677`、`main.py:747-756`、`main.py:782-796`。
6. **安静但可感知**：只在状态变化、选中建议和错误出现时动效；不让 480 格持续闪烁。现有样式去重与批量刷新应保留为实现经验，见 `main.py:760-767`。
7. **失败可见且可恢复**：错误卡必须含人话原因、影响范围和恢复动作；当前错误以模态弹窗为主，见 `main.py:220-222`、`main.py:889-891`。

## 2. 信息架构与导航

### 2.1 一级结构

| 区域 | 内容 | 设计依据 |
|---|---|---|
| 品牌/上下文 | “扫雷助手”＋当前棋盘规格、连接状态 | 配置与运行状态当前散落在控制器，见 `main.py:77-89` |
| 主导航 | 总览、自动运行、获取建议 | 对应现有三页，见 `ui/window.py:228-370`、`ui/window.py:371-544` |
| 支持导航 | 识别校准、运行设置 | 将“截图帮助”改为任务导向名称；当前命名见 `ui/window.py:554-560` |
| 全局状态条 | 当前阶段、耗时、目标窗口状态、停止入口 | 当前没有显式状态枚举，审查见 `review/全面审查-UI与调用流程-20261106.md:188-212` |
| 主工作区 | 当前页唯一主任务 | 避免说明、图例、棋盘与按钮同时争夺注意力，现状见 `ui/window.py:390-543` |
| 详情/检查器 | 当前建议或选中格的证据；无选中时给操作提示 | 替代当前模态解释框，现状见 `main.py:782-800` |

### 2.2 页面任务与默认焦点

- **总览 `/overview`**：两张模式入口卡、配置健康检查、最近一次结果；默认主操作为“获取下一步建议”，但页面加载时不主动抢焦点。不再以整屏使用说明替代任务入口，现有长说明见 `ui/window.py:561-577`。
- **自动运行 `/auto`**：状态条 → 当前决策卡 → 棋盘 → 运行统计；主按钮依状态为“开始自动运行 / 暂停 / 继续 / 停止”。现有自动入口先弹局数输入，见 `main.py:875-888`。
- **获取建议 `/assist`**：扫描状态 → 棋盘 → 建议详情 → 用户确认后的批量操作；默认选中最高价值候选，但不替用户点击。帮助线程及批量点击现状见 `main.py:508-619`、`main.py:821-849`。
- **识别校准 `/calibration`**：只承载模板与坐标校准；显示当前步骤、取消和重新采集，不再让用户靠静止等待猜测进度，现状见 `main.py:1037-1095`。
- **运行设置 `/settings`**：棋盘尺寸、总雷数、计算预算、程序路径、显示与无障碍；危险/高级项分组，保存前校验。现有多处弹窗输入见 `main.py:1016-1035`、`main.py:1097-1119`。

### 2.3 导航约束

- 运行中允许切换查看页面，但全局状态条与停止入口始终可见；不得用禁用所有导航代替互斥控制。当前运行会禁用左侧全部入口，见 `main.py:422-427`、`main.py:851-873`。
- 模式切换不隐式开始/停止任务；开始、暂停、停止都需明确事件与可见结果。
- 浏览器原型采用语义化 `nav`＋链接/按钮和 `aria-current="page"`；不伪造路由后端。

### 4.2 棋盘专用 Token

| 语义 | 背景 / 前景 / 标记 | 说明 |
|---|---|---|
| 已开数字格 | `#E4E9ED` / `#26343D` | 数字直接显示，不再以截图叠底 |
| 未开、无估值 | `#C5CDD3` / `#33414A` | 文本“—”与 tooltip“暂无估值” |
| 识别未知 | `#68727B` / `#FFFFFF` / `?`＋斜纹 | 必须触发恢复提示，不可当作普通概率格 |
| 已证明安全 | `#D5F0E4` / `#0C5138` / `✓` | 只有 `is_proven_safe=true` 才使用 |
| 已证明是雷 | `#F8D7D2` / `#8F1D14` / `旗` | 只有 `is_proven_mine=true` 才使用 |
| 推荐但未证明 | 原概率底色 / `#5B4400` / 2px 金色虚线框 | “推荐”不等于“确定安全” |
| 当前选中 | 原语义底色 / `#182128` / 3px `#006D77` 实线框 | 选中不等于推荐 |
| 推理涉及格 | 原语义底色 / 四角刻度标记 | 不再用紫色框覆盖概率与焦点语义 |

连续安全概率色阶：`0% #B42318`＋白字、`25% #D56A24`＋`#182128`、`50% #D2AD4A`＋`#182128`、`75% #73A888`＋`#182128`、`100% #217A5B`＋白字。五档文字对比度本地计算分别为 6.57、4.60、7.63、5.97、5.25:1。色带旁必须有 0/50/100% 刻度；格子同时显示整数百分比。上述五色为离散锚点，CSS 可线性插值但**不得用色相近似证明数值**；插值后仍需重新验文字对比度。当前 OKLCH 同源图例思路可保留，见 `ui/window.py:14-51`，但 HTML 原型先使用固定锚点确保一致性。

### 4.3 字体、尺寸、空间与形状

- 中文 UI：`"Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei", sans-serif`；标题同族 600/700，禁止以楷体承担产品个性。当前楷体/宋体依赖见 `ui/window.py:86-89`、`ui/window.py:120-124`。
- 数字与坐标：`"IBM Plex Mono", "Cascadia Mono", monospace`；概率使用 tabular numbers，避免刷新跳动。
- 字号：页面标题 28/36，卡片标题 18/26，正文 14/22，辅助 12/18，棋盘格 11–13px 且随格宽缩放；不以 9pt 小字承载关键信息，现状见 `main.py:686-690`。
- 间距基元：4、8、12、16、24、32、48px；卡片内边距桌面 24px、窄屏 16px。
- 圆角：卡片 12px、按钮 8px、标签 6px、棋盘格 3px；不使用大胶囊堆砌层级。
- 阴影：仅浮层 `0 8px 30px rgba(24,33,40,.12)`；普通卡片用 1px 边框，不用阴影制造层级。
- 控件最小高度 40px；主要操作 44px。现有批量操作仅 32px 高，见 `ui/window.py:516-528`。

## 5. 棋盘与热力图语义

### 5.1 一个格子只表达一组正交信息

| 维度 | 表达 | 禁止 |
|---|---|---|
| 棋盘事实 | 数字 0–8、未开、标雷、未知 | 未知不得强行归入 0–10，风险见 `review/全面审查-UI与调用流程-20261106.md:299-327` |
| 数值 | 安全概率 / 策略胜率 / 均匀先验，各自带类型标签 | 不统一称“非雷概率”，现状见 `main.py:769-780` |
| 建议 | “推荐”虚线框＋文字 | 推荐不得伪装为证明安全 |
| 用户选择 | 青蓝实线框＋详情面板 | 不用选择色改变风险色 |
| 推理上下文 | 四角刻度＋“涉及此格”文本 | 不用紫色框覆盖其它状态，现状见 `main.py:782-796` |

### 5.2 显示规则

1. 热力图默认仅展示可比较的 `exact_safety`，格内写“88% 安全”；`heuristic_win_rate` 与 `uniform_prior` 必须切换至各自独立视图，分别显示“62% 胜率”与“71% 先验”，不得把三类裸数值放进同一连续色带。
2. 概率保留整数百分比；详情可用一位小数并给出计算时间与世界数，避免伪精确。当前 UI 使用三位小数，见 `main.py:625-628`。
3. 证明安全与证明是雷优先于连续色带；`0%` 估计不自动等同“已证明是雷”。
4. 图例固定五项：已证明安全、已证明是雷、概率估计、推荐未证明、未知/无数据；不使用现有“高概率不是雷”等含混描述，现状见 `ui/window.py:583-588`。
5. 桌面格子最小 28×28px，触屏/高缩放最小 36×36px；30×16 棋盘在 28px 格宽下内容宽 840px，容器可横向滚动，不压缩到不可读。
6. 行、列标题固定；坐标统一 `(列, 行)`，从 1 开始。现有自动网格已有 0/1-based 转换风险注释，见 `main.py:692-699`，原型必须在数据层消解而非让组件各自换算。
7. 棋盘与详情消费同一 `snapshot_id`；旧快照用“已过期”徽标且禁用执行按钮。当前 GUI 首屏扫描与后台扫描分离但可能呈现不同来源，见 `main.py:508-619`。
8. 识别失败格显示 `?`，状态条进入“需要校准”，自动执行动作禁用；不以灰格或无概率静默带过。

### 5.3 详情卡字段顺序

1. 标题：建议点击 `(12, 8)`；2. 结论标签：已证明安全 / 概率估计 / 启发式建议；3. 主数值及正确单位；4. 一句原因；5. 决策路径、候选世界数、耗时；6. 涉及格 chips；7. 操作区。当前“当前决策卡片”需求见 `review/全面审查-UI与调用流程-20261106.md:235-255`。

## 6. 状态机可视化与反馈

### 6.1 状态文案与视觉

| 状态 | 用户可见文案 | 进度/动作 |
|---|---|---|
| `IDLE` | 就绪 | 无进度；开始按钮 |
| `STARTING_GAME` | 正在启动扫雷窗口 | 不定量进度；可取消 |
| `CALIBRATING` | 正在校准棋盘 | 步骤文本，如 1/2 |
| `SCANNING` | 正在读取棋盘 | 不定量进度；显示截图时间 |
| `DEDUCING` | 正在推理确定格 | 有真实计数才显示百分比 |
| `DECIDING` | 正在比较候选格 | 显示已用时间，不伪造完成率 |
| `WAITING_BOARD` | 等待棋盘画面稳定 | 显示等待与超时 |
| `CLICKING` | 正在执行点击 | 显示目标格；停止始终可用 |
| `CHECKING_RESULT` | 正在确认本局结果 | 不定量进度 |
| `PAUSED` | 已暂停，不会继续点击 | 主按钮“继续” |
| `STOPPING` | 正在安全停止 | 禁用新动作，保留状态 |
| `WON` / `LOST` | 本局已完成：胜利 / 失败 | 结果卡＋下一局/返回 |
| `ERROR` | 已停止自动操作 | 错误原因＋恢复动作 |

状态枚举依据 `review/全面审查-UI与调用流程-20261106.md:204-212`。阶段轨道只高亮“已完成—当前—后续”，不画装饰性全链路；默认压缩为“扫描 → 推理 → 决策 → 执行 → 确认”五段，悬停/聚焦显示真实状态名。当前进度由历史速度模拟，见 `main.py:351-367`，HTML 原型不得把估算动画当真实进度。

### 6.2 状态反馈规则

- 状态条包含图标、文字、最近动作、耗时、可用动作；颜色仅辅助。状态改变通过 `aria-live="polite"` 宣告一次，不逐帧播报。
- `ERROR` 卡显示“无法确认棋盘，因此未执行点击”，并给“重新扫描”“打开校准”两动作；识别失败不能沿用旧概率继续显示为最新结果。
- `STOPPING` 必须等完成事件后才显示“已停止”；当前直接终止线程的模式见 `main.py:399-420`，本规范只定义界面契约，不宣称后端已具备协作取消。
- `PAUSED` 保留最后可信快照及“快照时间”；继续前若过期先重扫。
- 成功提示不打断工作流；胜负结果可留在结果卡。避免当前每个错误/终止都弹模态框，见 `main.py:399-420`。

## 7. 自动模式交互

1. **开始前**：局数使用页内数字输入（默认 1，范围 1–10000 与现有一致，`main.py:875-880`）；同时展示棋盘规格、目标程序、计算后端和配置健康状态。
2. **启动**：点击“开始自动运行”后进入状态条；按钮立刻变为“暂停”和“停止”，禁止重复创建任务。局数不再用突兀弹窗承载。
3. **运行中**：棋盘可只读查看；点击格子更新右侧详情，不触发游戏点击。当前自动热力图是被动展示，见 `main.py:692-780`。
4. **暂停**：暂停只阻止后续动作，不清空证据；详情卡显示当前建议、最近动作、决策路径与快照时间。
5. **候选排序**：可展开候选列表；仅在相同 `value_kind` 内按数值排序，跨类型分组为“精确安全 / 策略胜率 / 均匀先验”，不按裸数值混排。每行含坐标、数值类型、数值、是否已证明；默认最多 5 行，完整列表可滚动。
6. **停止**：始终显示“停止”；点击后立即进入 `STOPPING`，禁止新点击。二次确认仅在当前正在执行批量点击时出现，不为普通停止增加摩擦。
7. **诊断**：提供“复制诊断”与“查看快照”；诊断含状态、快照 ID、配置摘要、错误码，不含隐私路径原文时采用脱敏显示。需求依据 `review/全面审查-UI与调用流程-20261106.md:235-255`。
8. **结束**：结果卡显示本局结果与累计局数/胜局/胜率，同时保留最后一次可信决策并标注“历史结果”。现有统计字段见 `main.py:769-780`。
9. **键盘**：优先提供明确的“暂停/继续”按钮，快捷键为 `P`（仅在焦点不位于输入控件且未按修饰键时生效）；`Ctrl+Shift+P` 保留为启动入口但运行中不得重复启动；`Esc` 不直接停止，只关闭详情/弹层。

## 8. 帮助模式交互

1. **获取建议**：主按钮“扫描并获取建议”；扫描期间棋盘骨架可见，禁止用全未开盘冒充识别成功。当前扫描失败会返回全 9 棋盘，见 `main.py:585-619`。
2. **选择格子**：鼠标点击或方向键移动即同步右侧详情；Enter 将焦点移入详情，不弹模态窗。详情按“结论—依据—涉及格—建议动作”组织，替代当前长字符串弹窗，现状见 `main.py:621-640`、`main.py:782-800`。
3. **推理次序**：单独显示为 `#1 / #2` 小徽标，不与已开数字争夺同一文本；提供“显示推理次序”开关，默认开。现有数字混合格内见 `ui/window.py:586-588`。
4. **涉及格高亮**：详情聚焦时显示四角刻度，并列出坐标；移出详情后恢复。无需通过禁用按钮实现高亮清理，现状见 `main.py:802-810`。
5. **批量执行**：按钮名“应用已证明的操作”，点击前显示摘要“将打开 3 格、标记 1 雷”，用户确认后执行；概率推荐永不批量自动点击。现有按钮会把安全点击与标雷一并执行，且 `is_best` 或 `confidence>=0.99` 也会进入点击集合，见 `main.py:652-659`、`main.py:821-846`；新原型只能依据显式证明标记，不得沿用该阈值。
6. **执行后**：自动重扫并以新快照替换结果；期间禁止重复执行，失败时保留旧结果但标“未应用/部分完成”，不能静默清空列表。
7. **模式边界**：帮助模式只提供建议与用户明确确认的操作；不因为进入帮助页就无限自动运行。当前帮助与自动 Solver 分离的既有事实见 `main.py:187-240`。
8. **空/无可行解**：显示“本轮没有可证明的操作”，仍允许查看概率候选；不要启用“应用已证明的操作”。

- 更新只变更受影响格；保持现有去重与原子刷新经验，见 `main.py:701-767`。

## 10. 无障碍与文案规范

1. 使用 `header/nav/main/section`、真实 `button`、可见标签；棋盘优先 `role="grid"`，每格 `role="gridcell"` 并可只读聚焦。
2. 棋盘采用 roving tabindex：仅当前格 `tabindex=0`，方向键移动，Home/End 到行首/尾，Ctrl+Home/End 到棋盘首/尾；行列读作“第 8 行，第 12 列”。
3. 每格 accessible name 示例：“第 8 行第 12 列，安全概率 75%，推荐但未证明”；已开格：“数字 2”；未知：“无法识别”。不得只朗读颜色。
4. 普通文字与背景对比度至少 4.5:1，大字至少 3:1；焦点、边框等非文字信息至少 3:1。实现时需用工具实测，本文不预先宣称全部组合通过。
5. 全局 `:focus-visible` 为 3px `#A13D00` 外环＋2px 白色间隔；焦点环不得被棋盘 `overflow` 裁切。
6. 状态更新用 `aria-live="polite"`；危险错误用 `role="alert"` 一次；计时器和概率刷新不连续播报。
7. 所有图标按钮有中文名称；tooltip 仅补充，不能承载唯一信息。现有 tooltip 时长被设为 1ms，见 `ui/window.py:61`，原型不得沿用。
8. 支持完整键盘操作、200% 缩放与减少动态效果；不用拖曳作为唯一操作方式。
9. 正式术语：`自动运行`、`获取建议`、`识别校准`、`安全概率`、`策略胜率`、`均匀先验`、`已证明安全`、`已证明是雷`、`推荐但未证明`、`无法识别`。
10. 禁用“帮助人类”“一定不是雷”（对非证明格）及把不同 `confidence` 都写成“非雷概率”；现有文案见 `ui/window.py:554-597`。错别字“下次不在显示”改为“下次不再显示”，见 `main.py:918-921`。

### 12.3 必备交互夹具

- **正常态：**上面的四候选至少覆盖精确安全、启发式胜率、均匀先验三种类型，并包含一个已证明安全格；用于 P0-UI-02。

- **过期态：**`snapshot_status="stale"`，保留最后证据并标过期，所有执行动作禁用。
- **停止态：**`solver.state="STOPPING"`，主文案“正在安全停止”；只有注入 `IDLE` 完成事件才显示“已停止”。
- **无可行解态：**候选为空，`error=null`，显示“本轮没有可证明的操作”，不伪造成系统错误。
- **胜负态：**分别注入 `WON` 与 `LOST`，显示结果卡、历史快照和累计统计。
- **错误态：**自动动作禁用，给重新扫描与校准入口，不能把旧概率标成最新结果。

## 13. 边界、未覆盖项与实施顺序

1. 本轮仅完成 UI 原型规范；没有修改 `main.py`、`ui/window.py`、`ui/window.ui`，也没有实现 HTML 或后端接口。
