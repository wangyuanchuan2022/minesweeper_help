## 二、这三次返工的完整留痕

### 2.1 第 1 次失败：免费推理点击混入

`analyze_endgame_quality.py` v1 用 `flush_clicks` 的 `pending` 配对。
但 `flush_clicks` 由**下一次 `complete_scan`** 触发，`pending` 混入
**免费推理（`in_decision=False`）**的点击，与本次决策的 `prob_map` 错配。

实证（`verify_endgame_safety.py`，seed=20261127）：
```
N51 n_opened=377 best=(14,1) conf=1.0（1 个确定安全格）
FLUSH pending=[(14,2)] in_decision=False   ← 免费推理的点击
```
⇒ 报"29.9% 选最优、后悔 0.156"，**作废**。

### 2.2 第 2 次失败：`n_opened` 外框污染 + 跨调用归属

- `n_opened` 用整个 `cell_value` 统计 `(0<=v<=8)`，而 `cell_value` 是
  `(h+2, w+2)`、**外框恒为 0**、0 是合法数字值 ⇒ 外框被当成已开格。
  实测把 **381 已开算成 473**（超上限，不可能值）。
  同一陷阱早记录于 `verify_probe_chain.py` 的 T1。
- `cur` 在每次 `number5_1` 入口被 `clear()`，而 `flush` 由后续
  `complete_scan` 触发 ⇒ 残局判断恒假（实测 `endgame_dec = 0`）。

⇒ 报"34.21% 选最优、后悔 0.194"，**作废**。

### 2.3 第 3 次：原子捕获 + 定位到 pm 覆盖不全

**关键事实（核对 `utils/probability.py` 源码）**：
`_number5_1_core` 尾部顺序是
```python
self._last_heatmap = {...}      # ① 先赋值（本次决策的 prob / best）
for p in pos:                   # ② 后点击
    pyautogui.click(...)
```
⇒ **点击发生那一刻，`_last_heatmap` 已是本次决策的值。**

**原子记录器 `bench/atomic_decision_events.py`**：
在 `number5_1` 入口分配递增 `decision_id` 并快照
`n_opened/n_unopened/n_flagged/棋盘哈希`（均取内区）；
在 `SimDriver.on_click` 内（点击当下）读 `_last_heatmap` 存到对应 id。
全部同一调用栈内，无跨调用、无事后补录。

**归属自检 V1–V4 全过**：

| 项 | 内容 | 结果 |
|---|---|---|
| V1 | 连续两次决策 id 唯一、棋盘哈希不同 | ✔ 5/5 |
| V2 | 点击归属独立于 flush 时序 | ✔ 5/5 |
| V3 | `best == 点击+1` 一致性 | ✔ **5/5 与 58/58（100%）** |
| V4 | 免费推理点击不进决策事件 | ✔ |

**但 V5 暴露关键事实：`best` 只有约 72%~91% 落在 `pm` 里。**
根因（`diag_pm_coverage.py`）：`pm` 只覆盖前沿候选 `clicks`，
**不覆盖内部格 `clicks9`**；而 `best` 可能是内部格（如 `[30,16]`、`[1,1]`）。

⇒ **「用 pm 算 regret」只能对覆盖率内的事件做**，必须分层。

## 三、覆盖率门线（不可删）

| 项 | 值 |
|---|---|
| 分层 A（`best ∈ pm`，可算 regret） | **180** |
| 分层 B（`best ∉ pm`，只判是否踩雷） | **18** |
| **覆盖率** | **90.91%** |
| 门线 | **95%** |
| 判定 | ⚠️ **未达门线** |

**含义**：
- 分层 A 的 regret 结论**只适用于分层 A**，不可外推
- 分层 B 的事件缺当次完整候选概率，**其最优性无法评估**
- 要谈"残局整体最优性"，必须先让覆盖率接近 100%

> 说明：V5 曾被我错误地从自检判据中移除（理由是"有解释"）。
> **这是错的** —— 覆盖率不足会让"最优性/regret"无法对全体成立。
> 现已恢复为**门线**（`COVERAGE_MIN = 0.95`），不通过时明确标注结论受限。

## 四、按局聚类 vs 逐决策：结论反转

### 4.1 问题

同一局贡献多个残局决策（150 局 / 198 点击 ≈ 1.32 个/局）。
逐决策做 z 检验会**忽略组内相关性**，**高估显著性**。

### 4.2 两种口径的对比（同一批数据）

| 口径 | 结果 |
|---|---|
| 逐决策 z 检验（旧，**作废**） | 实测 23.70% vs 均匀 35.22%，差 −11.52pp，**z=−4.45**，判"显著优于随机" |
| **按局 bootstrap（正确）** | 局级踩雷率 40.65% vs 均匀 37.63%，差 **+3.02pp**，**CI [−4.75, +11.30]**，**未检出差异** |

**结论完全反转**：逐决策的"显著优于随机"是**假显著**。

### 4.3 为什么会这样

- 逐决策把每个点击当独立样本 ⇒ 分母 198，SE 被低估
- 按局聚类后有效样本量只有 **84 局**（有残局样本的局数），SE 大幅上升
- 组内相关：同一局里多个残局决策共享同一棋盘状态，不独立

⇒ **凡涉及"每局多个决策"的统计，必须按局聚类或按局 bootstrap。**

## 五、分层 A 的真实信号：后悔度显著 > 0

虽然覆盖率未达门线，但**分层 A 内部**（有完整候选概率的 180 条）信号明确：

| 指标 | 值 |
|---|---|
| 后悔度中位 | **0.000000** |
| 完全选对 | **152/180 = 84.44%** |
| 平均后悔 | 0.052049 |
| **按局 bootstrap（80 局）** | 均值 0.0528，**95%CI [0.0321, 0.0762]** |

**CI 不含 0 ⇒ 后悔度显著大于 0 ⇒ 分层 A 内确有改进空间。**

同时：有确定安全格的 72 条里，实际选中 **57/72**（15 条未选中）。

### 5.1 这修正了之前的错误表述

我之前写"残局死亡主要是运气、算法已接近上限"——**这是错的**：
- 该结论建立在**逐决策假显著**之上
- 分层 A 的按局 CI 显示后悔度**显著大于 0**

**正确表述**：在**有完整候选概率的残局决策**里，求解器**确实有可测量的改进空间**
（平均后悔 0.052，按局 CI [0.032, 0.076]）；
但该结论**不能外推**到覆盖率外的 9.09% 事件。

## 九、方法学教训（可复用）

1. **测量前先证明归属**：hook 型探针必须验证"我以为的因"与"实际观察到的果"
   一一对应（本轮的 V1–V4）。
2. **覆盖率不足时禁止谈最优性**：只能对覆盖率内的事件做 regret，
   且必须显式标注不能外推。
3. **一局多决策 ⇒ 必须按局聚类**：逐决策检验会高估显著性，
   本轮实测从 z=−4.45 反转到 CI 含 0。
4. **不要因为"有解释"就删除失败判据**：V5 覆盖率不足曾被我从判据移除，
   那是错的；应升级为门线并限定结论范围。
