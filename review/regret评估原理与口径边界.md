## 一、核心思路

胜率要几千局才分辨 1pp，太慢；而一局里有几十上百个决策。
⇒ 改用**单步决策质量**作为指标，灵敏度高得多。

对某个决策点：

$$\text{regret}(c) = V^* - \text{after\_click}(c)$$

- `regret = 0` ⇒ 该步选对了
- `regret = 0.3` ⇒ 该步损失 30 个百分点

## 二、三个量的**准确**定义（这是修正后的口径）

### 2.1 `after_click(c)`

$$\text{after\_click}(c) = P(c\text{ 安全}) \times \mathbb{E}[\text{点开后继续求解的胜率}]$$

代码位置：`bench/arms_lookahead.py:388-399`

```python
def after_click(self, cell, wkey, opened):
    p_safe, outs = self.click_outcomes(cell, wkey, opened)
    for sub, op2, wt in outs:
        if self.won(op2):
            val += p_safe * wt
        else:
            val += p_safe * wt * self.V_exact(sub, op2)   # ← 递归
```

### 2.2 `V_exact`（不是"理论最优"）

代码位置：`bench/arms_lookahead.py:368-386`

```python
def V_exact(self, wkey, opened):
    self._tick()                       # ← 检查 node_cap / time_cap
    terms = self.saturate(wkey, opened)
    for wk, op, wt in terms:
        cands = self.candidates(wk, op)          # 完整候选集，无剪枝
        best = max(self.after_click(c, wk, op) for c in cands)  # 完整递归
```

**准确定义**：
> 在给定 `node_cap` / `time_cap` 内、对**完整候选集**做**完整递归**
> （无深度截断）得到的最大值。

**它不是数学上无条件的理论最优**，因为受以下限制：
1. `node_cap` / `time_cap` —— 超限时抛 `Budget`，**该决策点被整点丢弃**
2. 世界等权假设 —— Arbiter 布雷机制是否严格等价，**未逐位核对**
3. `candidates()` 定义依赖实现正确性

### 2.3 `regret`

> 「该评估器 + 该候选集内，实际选格相对最优选格的**条件**质量差」

**不是**完整对局的精确胜率损失。

## 三、实测验证（`bench/verify_after_click_semantics.py`）

### 3.1 基础件正确（safety）

构造 5×5、3 雷、中心已开且数字=1 的手算可验证局面
（世界数 = C(8,1) × C(16,2) = 960）：

| 项 | 结果 |
|---|---|
| 引擎世界数 vs 手算 | 960 = 960 ✔ |
| 环上 8 格 `safety` vs 手算 | **max\|差\| = 0.000e+00** ✔ |

⇒ `click_outcomes` 与 `safety` 这两个基础件正确。

### 3.2 探针结果：这些 cap 下**未求出值**

同一 960 世界的小局面，提高 cap 后：

| node_cap | 结果 | nodes |
|---:|---|---:|
| 100,000 | **未求出（node cap 超限）** | 100,001 |
| 1,000,000 | **未求出（node cap 超限）** | 1,000,001 |
| 5,000,000 | **未求出（time cap 超限）** | 1,388,544 |
| 20,000,000 | **未求出（time cap 超限）** | 1,357,824 |

**准确表述**：这 4 个 cap 配置下该局面**都没有求出值**。
这**不能**推出"已保留的点是近似值"——见 3.2b。

### 3.2b 关键区分：未求出 ≠ 已求出的是近似值

代码路径是（`arms_lookahead.py:282-286, 368-386`）：

```python
def _tick(self):
    self.nodes += 1
    if self.nodes > self.node_cap: raise Budget("node cap")   # ← 抛异常
    if 超时:                        raise Budget("time cap")   # ← 抛异常
```

`Budget` 是**异常**，调用方（`merge_and_eval_cases.py` /
`dump_metric_matrix_ext.py`）捕获后**整点丢弃**，不写入结果。

⇒ **已保留的 300 个成功点，是在 cap 内**完整递归跑完**的点**，
它们的 `V*` 没有被静默截断。

**因此必须严格区分两件事**：

| 说法 | 是否成立 |
|---|---|
| "有 47.5% 的点在给定 cap 下未求出值，被丢弃" | ✔ 成立（实测） |
| "已保留的 300 点是近似值 / 被截断" | ✘ **不成立**（Budget 是异常，不是静默截断） |

**真正需要担心的是自选择偏差**（留下的点偏向简单局面），
而不是"数值被截断"。这两者性质不同：
- 截断 → 每个点的数值不准
- 自选择 → 点的**集合**不代表性，但每个点的数值是对的

### 3.3 真实样本上的失败率（47.5%）

对 462 个合格点的前 40 点诊断：

| 结果 | 数量 | 占比 |
|---|---:|---:|
| ok | 21 | 52.5% |
| **Budget: time cap** | **19** | **47.5%** |

⇒ **接近一半的决策点因超时被丢弃。**

## 四、这对 P1 读数意味着什么（必须一起引用）

### 4.1 样本不是随机子集

被丢弃的 47.5% 是**计算上更复杂**的点 ⇒ 留下的 300 点**系统性偏向简单局面**：

| 项 | 留下的 300 点实测 |
|---|---|
| `limitation` | 8.01 ~ **26.33**（中位 10.79）|
| 世界数 | 2 ~ 6480（中位 **186**）|
| 候选格数 | 2 ~ 50（中位 22）|

而真实对局里 `limitation` 中位数是 **61**、p90 是 **380**。

**⇒ 这 300 点不能代表中局主力，只能代表"最容易被完整求解的那一小部分"。**

这正是本项目纪律第 4 条（对照组必须是真对照）警告的**自选择偏差**。

### 4.2 `V*` 是"该评估器内的最优"，不是"真实最优"

因为 `after_click` 递归到后续时同样受 cap 限制。
**成功返回的点** = "在该 cap 内完整递归跑完的点"，其 `V*` 就是该 cap 下的完整递归值。

但仍有两点限制：
1. **cap 敏感性未针对成功点验证**：需对成功点做"提高 cap 后 `V*` 是否不变"的
   对照（本脚本的探针只在**未求出**的局面做过，见 3.2）。这是待办（P1-b）。
2. **世界等权假设**未与 Arbiter 布雷机制逐位核对。

⇒ 不能声称"成功点的 `V*` 已证明准确"，只能声称"它们在该 cap 内完整递归跑完了"。
精度验证需另做（提高 cap 不变性 + 已知答案对照）。

### 4.3 不能线性外推到整局胜率

一局几十个决策，每个 regret 0.006 **不能**相加成 24pp。因为：
- 很多决策点不影响最终结果
- 早期决策的 regret 改变后续局面

**regret 改善 → 整局胜率改善的转换关系，本轮未量化。**
