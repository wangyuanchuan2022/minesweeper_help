# F 矩阵是什么，以及它的口径边界

日期：2026-11-04　分支：main

---

## 一、F 矩阵的定义

**F 矩阵 = 每个候选格在 7 个启发式指标上的打分表。**

### 结构（以一条真实记录为例）

```json
{
  "limitation": 9.522,
  "n_cand": 18,
  "coords": [[1,13], [2,13], [3,13], ...],   // 18 个候选格坐标
  "q":      [0.7556, 0.2000, 0.7556, ...],   // 18 个评估值（见第二节口径）
  "F": {
    "S0": [1.00, 0.00, 1.00, ...],           // safety 归一化打分
    "IG": [0.42, 0.88, 0.31, ...],           // 信息增益
    "U":  [...], "E": [...], "B": [...],
    "R":  [...], "L": [...]
  }
}
```

**形状：`7 × n_cand`**（7 个指标 × 候选格数）。

### 七个指标

| 行 | 含义 | 方向 |
|---|---|---|
| `S0` | 安全概率（1 − P(雷)） | 越大越好 |
| `IG` | 信息增益：点开后预期新开格数 | 越大越好 |
| `U` | 两步最坏存活：`safety × min(后续最差安全率)` | 越大越好 |
| `E` | 预期安全格数 | 越大越好 |
| `B` | 约束块强度 | 越大越好 |
| `R` | 尾部风险（后续被迫猜测的风险） | **越小越好**（已取负） |
| `L` | 到边界距离（位置先验） | 越大越好 |

**每个决策点内部做 min-max 归一化到 [0,1]**，否则量纲差几个数量级
（IG 是格数、S0 是概率），权重会被量纲完全支配。

## 二、`q` 的准确口径（Advisor 纠正后的表述）

### 2.1 它是什么

`q[i]` 是候选格 `i` 的 `after_click` 值，来自 C++ `exact_eval`
（与 Python `ExactEngine.after_click` 逐位对拍 140/140 通过）。

**准确定义**：
> 在**当前世界模型**（世界等权）、**当前候选集**（`candidates()` 定义）、
> 且**该点成功完成完整递归**（未触发 `node_cap`/`time_cap`）的条件下，
> 算出的「该格安全概率 × 点开后继续按该评估器最优续玩的期望值」。

### 2.2 它**不是**什么（必须避免的越界）

| 不能说 | 为什么 |
|---|---|
| ❌ "真实价值" | 它依赖世界等权假设，未与 Arbiter 布雷机制逐位核对 |
| ❌ "精确 after_click" | 只在"成功完整递归"的点上有值；47% 的点因超时被丢弃 |
| ❌ "全局胜率真值" | 它是**单步**评估，不是整局胜率；两者转换关系未量化 |

### 2.3 正确用法

> `q` 可作为 **P1 的优化代理**（proxy）：用它来给候选格排序、
> 计算 regret、驱动权重搜索。
>
> **但最终是否提高胜率，必须由独立的整局 A/B 确认。**
> 优化器会**放大**这个代理的任何偏差——所以不能在整局验证之前
> 声称"权重优化提高了胜率"。

## 三、F 矩阵与 q 的分工

| | 是什么 | 谁提供 | 用途 |
|---|---|---|---|
| **q** | 候选格评估值（口径见第二节） | C++ `exact_eval` | **优化目标**（代理） |
| **F** | 候选格在各指标上的打分 | Python 计算 | **优化的自变量** |

**优化的本质**：

> 找一个权重向量 `w`，使得 `argmax(w · F)` 选中的格，
> 其 `q` 尽可能接近 `max(q)`（即 regret 尽可能小）。

没有 F，就不知道每个候选格在各指标上打多少分，**无法计算任何线性组合**。

## 四、为什么必须"扩样"

当前数据状况：

| 文件 | n | 有 F？ | 用途 |
|---|---:|---|---|
| `mm_discovery.json` | **77** | ✅ | 可优化（但样本小） |
| `merged_regret.json` | 300 | ❌ | 只有 q，不能优化 |
| **`mm_full.json`（扩样中）** | 目标 ~300 | ✅ | **扩样目标** |

**"F 矩阵扩样" = 把有 F 的点从 77 扩到 300+，让权重优化有足够样本。**

### 为什么 77 点不够

7 维连续权重、77 个点 ⇒ 参数/样本比 ≈ 1:11，**高过拟合风险**。
实测证据（77 点，`bench/optimize_weights.py`）：

| 方法 | in-sample regret | **LOO regret** |
|---|---:|---:|
| S0 单指标（零参数） | 0.0161 | 0.0161 |
| 随机搜索 | **0.0140** | **0.0271** |
| 坐标下降 | **0.0113** | **0.0228** |

**in-sample 都变好，LOO 都变差** ⇒ 这是过拟合的直接证据。

## 五、口径边界汇总（引用 F/q 时必须一起说）

1. `q` 是**当前世界模型 + 当前候选集 + 成功完整递归**条件下的评估值，
   不是无条件精确的全局胜率真值。
2. `q` 只在**成功完成递归**的点上有值；被丢弃点存在**自选择偏差**
   （P1-c 全样本分层统计见 `state/ab/p1_coverage.json`）。
3. `q` 是**单步**量，**不能**线性外推成整局胜率提升。
4. 权重优化的结果**必须**经独立整局 A/B 确认，才可声称提高胜率。
5. 验证集（`midgame_cases_ext2.json`）**只评估一次**，不得反复查看。
