## 三、P0-3 评估器单分支截断：**实测确认，并量化了危害**

### 3.1 代码事实

`bench/dump_metric_matrix_ext.py:316-317`：

```python
terms.sort(key=lambda t: -t[2])
wk2, op2, _wt = terms[0]      # ← 只保留权重最大的单个终端分支
cands = eng.candidates(wk2, op2)
```

而 `bench/arms_lookahead.py:298-328` 的 `saturate()` 在多观测分支时会
**返回多个终端态** `res.extend(...)`，带各自权重。

⇒ 除 `terms[0]` 外的终端分支及其概率质量被**静默丢弃**，
F 的 minmax 归一化与 q 都只在**被截断的单一分支**上计算。

### 3.2 在真实数据上的危害（不是构造用例）

方法：对 `mm_full.json` 的 ok 点重跑 `eng.saturate()`，
按与脚本**完全同口径**的过滤（`not won and candidates`）统计终端条数与权重。

**前 60 个真实 ok 点：**

| 终端分支数 | 点数 |
|---|---:|
| 1（无截断） | 48 |
| 3 | 2 |
| 4 | 1 |
| 8 | 1 |
| 10 | 1 |
| 24 | 2 |
| 27 | 1 |
| 30 | 1 |
| 38 | 1 |
| 140 | 1 |
| 192 | 1 |

- **12/60 = 20.0% 的点存在多终端分支**
- 丢弃概率质量 `1 − top_weight/Σweight`：**中位 81.5%，均值 76.8%，最大 98.6%**

⇒ 在约 1/5 的点上，被当成"真值"的 q 只覆盖不到 19% 的概率质量（中位情况）。

### 3.3 与审计表述的一处技术差异（需复核）

审计 P0-3 称「q 由 C++ exact_eval 从**原状态**独立饱和，F 与 q **状态不同源**」。
我逐行核对 `dump_metric_matrix_ext.py:322-327` 后认为：

```python
worlds = [format(eng.world_bits[k], "x") for k in wk2]   # ← 用的是 wk2 = terms[0]
```

即 **q 与 F 用的是同一个（被截断的）状态 `wk2`**，两者同源。
真正的问题是「截断」而非「q/F 不同源」。
此项待审计席复核；若我读错，需指出具体行号。

### 3.4 处置决定（已执行）

- **已停止** 85 点重试进程（停时产出 19 点，**未生成 `mm_retry2_out.json`、未并入任何主矩阵**）。
- 接受并强化审计结论：**P0-3 修复前，`mm_full.json`(287)、`merged_regret.json`(300)
  及全部基于它们的 LOO / 权重结论，整体不可作为结论依据。**
- 补充理由：多终端分支**集中在复杂局面**，而权重优化的目标正是改善复杂局面
  ⇒ **缺陷与目标变量高度相关**，不能假定偏差随机、可忽略。

## 六、本轮结论汇总（按证据强度）

1. **真实未覆盖率 = 59.7%**（186/462 ok），自选择偏差偏向复杂局面（worlds 中位差 18.7 倍）——全样本实测，替代 47.5% 误传。
