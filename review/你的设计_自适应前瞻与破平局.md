## 三、按你的设计，方案应这样定义（待你确认后实做）

### 3.1 决策流程（三阶段）

```
阶段 1：算 S0（所有候选的安全概率）—— 必须，成本与现状相同
阶段 2：判定平局集
        平局定义：safety(c) >= max_safety - eps
        eps 应按局限度取值（简单局面可严，复杂局面放宽）
阶段 3：对**平局集**内的候选算 ply_score(k)，按前瞻值选最高者
        若前瞻后仍平局 → 回退到启发式破平局（如开格数期望）
```

**前瞻深度 k 与复杂度挂钩**：
```
k = k_max                     若 limitation <= T_low     （简单局面：可算深）
k = k_max - floor((limitation - T_low)/Δ)   中等复杂度：逐级变浅
k = 1（即不做前瞻，用 S0/safety） 若 limitation > T_high （复杂局面：算不动）
```

⚠️ 其中 `T_low / T_high / Δ / k_max` 都是**待定参数**。
   按历史教训，不能凭直觉设值，必须先测真实分布。

### 3.2 必须先测的三件事（在任何 A/B 之前）

| 要测的 | 为什么 |
|---|---|
| **平局集大小分布**（按 limitation 分层） | 决定阶段 3 要算多少个候选格 ⇒ 决定成本 |
| **各 limitation 下 ply_score(k) 的单点耗时** | 决定 k 的自适应规则取值 |
| **自适应规则的触发率** | 避免重犯 ad1 的"0/248 从不触发" |

### 3.3 我已有的部分数据（可直接用）

从 `diag_minmax_tie.py`（148 点，worlds 2~180）：

| 项 | 读数 |
|---|---|
| 并列集唯一（无并列） | 52/148 = 35.1% |
| 存在并列 | 96/148 = 64.9% |
| 并列集大小 | 2~12 个（中位 2） |

⇒ 在**简单局面**上，平局集通常很小（中位 2），阶段 3 只需算 2 个候选的 ply_score，
   **成本远低于"全候选都算 3-ply"**。这支持你的设计。

⚠️ 但这是 worlds 2~180 的数据；深局面的平局集大小**未测**。
