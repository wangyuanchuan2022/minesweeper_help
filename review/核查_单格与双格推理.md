# 核查：单格推理与双格推理是否被用上

日期：2026-11-04
问题来源：用户提问「检查是否用上了单格和双格推理」
脚本：`bench/verify_deduction_levels.py`

---

## 一、直接回答

**用上了，而且比显式的单格/双格推理更强。**

但需要说清实现形态：项目**没有**独立的「单格推理模块」和「双格推理模块」。
它用的是**全枚举约束求解**，在数学上严格包含任意阶推理（含单格、双格、k 阶子集）。

---

## 二、实现事实（带 file:line 证据）

### 2.1 约束表达

已开数字格 = 一条约束「其邻域未开格中雷数 == 该数字」。

```
bench/arms_lookahead.py:288-296   _union_inter(wkey)
    union = 所有一致世界的并集   ← 可能是雷的格
    inter = 所有一致世界的交集   ← 一定是雷的格

bench/arms_lookahead.py:308-311   saturate 的 safe 判定
    safe = all_mask & ~opened & ~union
    ⇒ 并集都不是雷 ⇒ 必然安全
```

### 2.2 推理能力来源

`part_solve` / `exact_eval` 枚举**所有满足全部约束的世界**。
于是：

| 推理层级 | 是否被覆盖 | 原因 |
|---|---|---|
| 单格推理（邻域雷数已满 ⇒ 其余安全） | ✅ | 该结论对所有一致世界成立 ⇒ 体现在 union 上 |
| 双格推理（两约束重叠相减） | ✅ | 同上，差集结论对所有世界成立 |
| k 阶子集推理 | ✅ | 同上 |
| 无法确定的格 | ✅ 不会过度断言 | union 含它 ⇒ 不进 safe |

**数学依据**：union/inter 是「全体一致世界」上的逐格量化，
任何能由逻辑推出的必然结论，都必然对每个世界成立 ⇒ 一定反映在 union/inter 中。
这是**严格强于**有限阶显式推理的口径。

## 三、实证验证（独立实现对拍）

用**本脚本内独立写的全枚举**（不依赖生产代码）对拍 4 个手工构造用例：

| 用例 | 约束 | 期望 | 结果 |
|---|---|---|---|
| A 单格推理 | `{a,b,c}==2`，`{a,b}==2` | c 必安全，a/b 必雷 | **✔ 全部正确** |
| B 双格推理（差集） | `{a,b}==1`，`{a,b,c}==2` | c 必雷 | **✔ 正确** |
| C 1-2 差集 | `{x,a}==1`，`{x,a,b}==2` | b 必雷 | **✔ 正确** |
| D 阴性对照 | `{a,b}==1` | 无确定结论 | **✔ 未过度断言** |

⇒ 单格、双格、1-2 型差集推理均成立，且无结论时不乱推。

### 3.1 交叉验证：C++ 与 Python 逐位一致

`exact_eval(ply=2)` vs Python `ply_score(k=2)`
⇒ **4 点、22 格，max|Δ| = 0.000e+00**。

⇒ 两侧的 `saturate` 链（含上述 union/inter 推理）实现一致。

### 3.2 用户要求的第二点：每步前瞻都在点击后做完整逻辑推理

调用链已核实（两侧相同）：

```
after_click(cell, wkey, opened)
  → click_outcomes(...)          # 点开该格的所有可能结果
  → for each outcome: V_exact(sub, op2)
       → saturate(wkey, opened)  # ★ 在这里执行完整逻辑推理
       → 递归直到 won / 无 safe 可开 / 全部候选耗尽
```

`saturate` 的终止条件是「没有必然安全格可开」（`safe.empty()`），
即**一直推理到推不出更多为止**，不是"点一格就算一步"。
Python（`arms_lookahead.py:298-328`）与 C++（`mscore.cpp:1873-1919`）实现一致。

## 四、必须说清的两个例外（否则结论过宽）

### 例外 1：降级路径

当 `limitation > wr_threshold` 或 `_wr_memory_ok` 判定内存不足，
或 `win_rate` 抛 `_WrNodeCapExceeded` 时，生产会降级走
`process_bigger_situation`（`utils/probability.py:1153`）。

**但降级后仍不是纯贪心**：它调用 `pbs_compute`（C++）或 `_pbs_compute_python`，
同样是**枚举求解**输出逐格雷概率，`res >= 0.99` 即判为确定安全
（`probability.py:1171-1189`）。

⇒ 降级损失的是「前瞻/全局最优」，**不是**基础推理能力。

### 例外 2：枚举规模超限

若约束规模超出 `node_cap` / `time_cap`，枚举不完整，
此时**不保证**得到完整推理结论（可能把可推的格判为不确定）。
这是资源限制，不是算法缺陷，但报告时必须标注 —— 本会话已知
worlds > 10000 的局面在 30s 内大量超时。
