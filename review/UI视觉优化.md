## 一、结论摘要（先看这四条）

1. **有三处文字实际读不出来**：主页面说明文字白字压在高光照片上（最差对比度 **1.02**，最大一行有 **43% 的像素低于 AA 4.5**）；左侧栏**禁用态文字完全消失**（白 175 文字压在白 150 底上，对比度 **1.00**）；进度条百分比文字在进度过半后压到深色渐变块上（黑字对比 **1.31~1.80**）。
2. **有一处内容真的被裁掉了**：主页面 `frame_4` 的 `minimumHeight(200) > maximumHeight(160)` 自相矛盾，导致最后一行说明（`label_16`：「将鼠标移到左上角强制结束自动扫雷」）底边 206 > 容器 200，被切掉。
3. **热力图色带是红绿对立色**：红绿色盲下 p=0.40 与 p=0.60 两档的模拟色差仅 **ΔE≈16**（几乎同色），而这两档恰好是"略偏雷"与"略安全"的分界——最需要分辨的位置最分不出来。且**帮助页图例与现场色带根本不是同一条**（图例中点 `#807f00`，现场中点 `rgb(247,149,0)`）。
4. **整体视觉语言没统一**：三页是三种风格（主页=照片上裸文字、自动页=磨砂卡片、帮助页=无衬底裸文字）；字号 7 档无模数；圆角 4 种（含一个非法值 `none`）；图标全为纯黑单色但尺寸 16/24/30 混用；背景图被拉伸形变 43.9% / 47.6%。

### 分级计数

- **P0（读不清/被裁切，必须修）: 4** —— 主页说明白字压花背景（最差 1.02）、侧栏禁用文字消失（1.00）、进度条黑字压深色块（1.31~1.80）、`frame_4` min/max 冲突致末行被裁（206 > 200）
- **P1（明显不一致/误导）: 9** —— 图例与现场色带不同源、图例 5px 错位、红绿色盲不可分（ΔE≈16）、热力图 43% 空白、网格字色靠继承、非法圆角 `none`、字体内混排/6 档字号、已开格白字余量仅 0.3、统计栏溢出截断
- **P2（打磨）: 8** —— 背景图形变 43.9%/47.6%、侧栏白纸化、三页视觉语言不统一、图标三套尺寸且无 disabled 态、`.scaled()` 锯齿、绝对坐标布局脆弱、色带亮度编码未利用、无主题令牌（13 色硬编码）

## 二、P0 —— 信息读不清 / 被裁切

位置: ui/window.py:189
严重度: [CRITICAL] P0
证据: `'QLabel{color:rgb(255, 255, 255);font: 10pt "楷体";min-height:26px}\n'`
问题: 主页面 7 行说明文字是**纯白字直接压在摄影背景上，没有任何衬底（scrim）**。背景图 `background_1.bmp` 是有云/高光的照片（平均 RGB `(96.8, 103.9, 95.7)`，但亮部达 `(255,255,226)`）。
现象（用户视角）: 说明文字在背景亮处（云、天空、高光）**几乎看不见**，在暗处才清楚。同一句话一半能读一半读不出来，观感像"文字渲染坏了"。
证据（实测，逐 label 对渲染像素统计）: `label_10` 最差对比度 **1.02**（背景 `rgb(255,255,226)`）；`label_13` / `label_14` / `label_16` 有 **41.8% / 42.8% / 41.3%** 的像素低于 AA 4.5；`label_15` 27.3%。中位数 8~12（说明一半以上区域是好的，坏的是亮部条纹）。
影响面: 首页是用户第一次打开看到的全部说明文字（怎么用、怎么配、出问题怎么办），读不全直接影响上手。
置信度: 高（真实渲染像素逐点计算 WCAG 对比度）
修复: 给说明区加半透明深色衬底卡片。实测阈值：卡片 `rgba(20,20,20,alpha)` 叠在最亮背景上，**alpha ≥ 0.60** 时白字才过 AA（alpha=0.6 → 合成 `rgb(114,114,103)`，对比 4.86；alpha=0.7 → 6.90）。建议与 `heatmap_frame` 同款磨砂卡（`rgba(44,44,44,170)` = alpha 0.667，实测可过），顺带统一视觉语言。
收益: 全部说明文字达到 AA；与自动页的磨砂卡片风格统一。
风险: 几乎无（加一个 QFrame 父容器 + 内边距，不改逻辑）。

严重度: [CRITICAL] P0
证据: `color:rgba(255, 255, 255, 175);`
问题: 左侧栏三个主按钮（自动/帮助人类/截图帮助）的 **disabled 态**里，文字色 `rgba(255,255,255,175)` 压在底色 `rgba(255,255,255,150)`（ui/window.py:97）上——两者都是白色，只差 25 的 alpha。
现象（用户视角）: 点「自动」后三个按钮变灰，**文字直接消失**，只剩三个空白的白色长方形。用户看不出哪三个按钮被禁用了、也看不出按钮上写的是什么。
证据（实测）: 禁用态 `auto_play` / `help_human` / `screenshot_help` 的「底色 vs 文字色」对比度均为 **1.00**（完全同色）；作为对照，`setting_2` 因为用了另一套 QSS（文字 `rgb(210,210,210)`）反而有 13.89——**四个按钮里三个瞎一个正常**，更显得像 bug。

风险: 无。

位置: ui/window.py:294
严重度: [CRITICAL] P0
证据: `"QProgressBar {border: none;border-radius: 12px;text-align: center;}\n"`
问题: 进度条 QSS **只设了背景和 chunk 渐变，没设 `color`**，于是百分比文字继承 palette 的 `WindowText`（实测 `#000000` 黑字）；而 chunk 渐变是 `rgb(167,255,245) → rgb(4,126,127)`（亮青→深墨绿）。

置信度: 高（真实渲染取样 + 逐值验证）

收益: 全程可读，且不需要改布局。
风险: 渐变改浅会减弱"进度感"，但对比度优先。

## 三、P1 —— 明显不一致 / 误导

位置: ui/window.py:343
严重度: [HIGH] P1
证据: `"background-color:qlineargradient(spread:pad, x1:0, y1:0, x2:1, y2:0, stop:0 rgba(255, 0, 0, 255), stop:1 rgba(0, 255, 0, 255))"`
问题: 帮助页的**色带图例**用 Qt sRGB 线性渐变（红→绿），而真实格子用 OKLCH 感知均匀渐变（`main.py:55-56`）。两条曲线完全不同。
现象: 用户照图例估色 → 系统性读错。**中点偏差极大**：图例中点 `#807f00`（暗橄榄），现场中点 `rgb(247,149,0)`（亮橙）。也就是说图例告诉你"50% 是暗黄"，实际画出来是"50% 是亮橙"；用户会把 50% 的格子误判成 65~75%。
证据（实测）: 图例左/中/右 = `#fc0300 / #807f00 / #03fc00`；`oklch_grad` 左/中/右 = `rgb(254,0,0) / rgb(247,149,0) / rgb(0,255,0)`。
影响面: 帮助页的核心是"看颜色判概率"，图例错了等于量具错了。
置信度: 高（两条色带逐点计算）
修复: 图例改成由同一份 `oklch_grad` 生成——`QLabel` 换 `QWidget`+`paintEvent` 逐列 `fillRect`（100 列，成本忽略），或 QSS `qlineargradient` 里按 10 个采样点插 stop（够近似）。
收益: 图例与现场完全一致。
风险: `ui/window.py` 是 pyuic 生成物，改动会被下次 pyuic 覆盖 → **应改 `ui/window.ui` 源文件**，或在 main.py 里代码内动态生成（推荐后者，不动 ui 文件）。

位置: main.py:56
严重度: [HIGH] P1
证据: `oklch_grad = gradient_gen.create_gradient([(1, 0, 0), (0, 1, 0)])`
问题: 概率色带是**红→绿对立色**。红绿色盲（deuteranopia/protanopia，男性约 8%）无法区分这两个端点附近的色相。
现象: 色盲用户看到的热力图中间段几乎是同一片颜色，"哪里安全"完全读不出来。
证据（实测，Viénot 矩阵模拟）: p=0.40 与 p=0.60 在 deuteranopia 下模拟为 `rgb(206,216,37)` vs 未列（ΔE≈**16**，视为不可分）；对比之下 p=0.0 vs 0.99 的 ΔE=142（可分）。**最需要细分的中间段恰恰最不可分**。
影响面: 约 8% 男性用户可用性直接受损；即使非色盲，中间段（最常见）也缺乏区分度。
置信度: 高（色觉模拟 + 色差计算）
修复: 改用**单色相亮度渐变**（同色系深浅，色盲 100% 可辨）或**蓝-橙发散**（CVD 安全）：浅灰 `rgb(247,247,247)` → 深蓝 `rgb(32,84,147)` 表示 0→100%。再叠加**冗余编码**：最佳格已有蓝框、必雷格已有红底，中间段可再用格子内小圆点大小/透明度辅助。另用 `max(黑,白)` 策略自动选字色（实测 100 个色阶最小对比度 5.21，全部过 AA；现有黑字方案最低到 5.21 也过，但换成深蓝后必须切白字）。
收益: 色盲可用 + 中间段可分辨；兼具"深浅=概率"的直觉映射。
风险: 更换色带会让老用户不习惯，建议保留旧色带作为可选（`cfg` 加一项 `heatmap_palette`）。

## 五、视觉设计建议（按性价比排序，非条目式问题）

1. **一次"统一到深色磨砂"的主题改造（最高杠杆）**：三页全部改为「照片背景降饱和/加蒙版 → 半透明深色卡片承内容 → 圆角 10px → 白字 + 灰次级字」。这一改动同时解决 P0-1（说明文字衬底）、P1-5（空白 43%）、P2-1（背景形变）、P2-2（侧栏刺眼）、P2-4（三页不一致）**五条**，是本报告唯一"改一次抵五次"的动作。
2. **色带重做 + 冗余编码**：单色相深浅（或蓝橙）+ 必雷/必安全保留实色块 + 最佳格保留蓝框 + 中间段加"概率数字"小字（可选开关）。解决色盲与中间段不可分。
3. **排版系统**：字号 3 档（10/12/15）+ 行高 1.5 + 间距 6/12/24 三档 + 说明区改自动换行布局。解决字体内混排与"1px 余量"脆弱。
4. **状态语义色化**：把"运行中/已停止/出错"用统一的状态色（青绿=运行、琥珀=等待、红=错误）表现在按钮、状态栏、边框上，替代现在"靠文字"的表达。
5. **微动效**（可选，勿过量）：`QStackedWidget` 切页加 150ms 淡入（`QGraphicsOpacityEffect` + `QPropertyAnimation`）；进度条 chunk 用 `QPropertyAnimation` 平滑过渡；按钮 hover 用 `QGraphicsColorizeEffect` 而非瞬变。注意：热力图不要加动画（会放大交互域报告的每帧重绘成本）。

## 六、验证方法（可复现）

本轮全部读数为本机实测，复现条件：`D:\anaconda3\envs\py310\python.exe`（Python 3.10.16 / PyQt5 5.15 / Pillow 9.5.0），`QT_QPA_PLATFORM` 下离屏 + 真实平台双跑。方法：
- **对比度**：`QWidget.grab()` 取真实渲染像素 → 相对亮度 → `(L1+0.05)/(L2+0.05)`；AA 阈值 4.5（正文）/3.0（大字）。
- **色盲模拟**：Viénot 1999 简化矩阵（deuteranopia/protanopia），在 sRGB 空间做线性近似；用模拟后的欧氏距离近似可区分度（<30 视为危险）。
- **几何/字体**：`QWidget.geometry()` / `QFontMetrics.horizontalAdvance()` 逐控件与文本宽比对。
- **形变**：图像原始宽高比 vs 控件宽高比。
- 口径说明：对比度与色差均为**本机当前背景图**下的实测值；换背景图后绝对值会变，但"哪里最差/差多少倍"的结论不变。

## 正面观察

- 自动页的**磨砂卡片体系本身是对的**：`rgba(44,44,44,170)` + `1px rgba(255,255,255,70)` 描边 + 10px 圆角，实测在照片背景上稳定给出 `#2c2c2c` 衬底，白字对比充足。这套设计**应该扩展到另外两页**，而不是重造。
- `heatmap_label_stats` 用胶囊形态 + `padding: 4px 10px` 紧凑不撑满，宽度自适应的思路正确（只是缺省略处理）。
- 热力图配色**有意区分了"必雷/必安全/概率/已开"四类**，语义分层是对的（红/绿/渐变/浅灰），只是色带本身选色对色盲不友好、字色靠继承。
- `_HM_BASE` 与样式去重机制（`main.py:753-758`）把"不必要的重绘"挡住了，视觉上因此**不会闪烁**——这是很多 Qt 程序做不好的地方，这里做对了。
- 侧栏 `NoFocus` 的设计（见交互域报告）在视觉上没有副作用，按钮外观不受焦点框干扰，观感干净。
