## 三、覆盖率：仪器、口径与读数

### 3.1 仪器（先验证再信任）

`coverage.py` 的 pip 安装在沙箱内两次失败（代理/网络不可用），改用自建无外部依赖探针 [tools/coverage_probe.py](../../tools/coverage_probe.py)：
- `sys.settrace` 两级 tracer（全局只在 `call` 事件判文件归属，非白名单 frame 返回 `None`，不再逐行回调）。首版对每一行（含 numpy/Qt/unittest 全部第三方代码）回调，307 项测试 **18 分钟无输出**，已终止并重建。
- **注入必红负向自测**：`output/_probe_selftest.py` 造 3 行必命中 / 2 行必不命中的夹具，PASS（阳性 L2/3/4 命中、阴性 L5/L8 未命中）。
- 自测暴露分母口径错误：模块级 `def/class/import` 声明行在 import 期执行，tracer 只在跑测期挂上，算进分母会让 100% 结构性不可达。已改为只统计**函数/方法体内**可执行语句行（5287 → 4604 行）。

### 3.2 口径（必须随读数一起声明）

- 分母：22 个生产 Python 模块的 AST 可执行语句行；排除 `ui/bg_rc.py`（10MB Qt 生成资源）、`__init__.py`、`bench/` 210 个历史脚本、`sim/`、`tests/`、`tools/`、文档与二进制。

## 四、为什么 100% 在这个沙箱里不可达（诚实边界）

剩余 1266 行未覆盖，按性质分三类：

| 类别 | 大致行数 | 典型位置 | 能否在沙箱内覆盖 |
|---|---|---|---|
| **真实 GUI 事件回调 / Qt 主循环** | ~455 | `main.py` 按钮点击、悬浮预览、设置对话框 | **否**。Qt offscreen 只能实例化，不能驱动真实事件链；强行 mock 会违反「尽量用真实数据」 |
| **真实 Arbiter / 屏幕 / 鼠标路径** | ~355 | `solver.py` 的 `play()` QThread 主循环、`vision.py` 抓屏/模板匹配、`mm0.py` 的 `GetMousePosition` 无限循环与 `MouseWindow` 抓屏叠加层 | **否**。沙箱低完整性级别 `SetCursorPos`/`SendInput` 失败，`ImageGrab` 间歇 `OSError`；真实 E2E 必须由用户在自己终端跑 `run_e2e_900.cmd` |
| **C++ 失败路径 / 防御分支** | ~108 | `probability.py` 决策不可用各出口、`e2e_probe` 异常吞掉分支 | 部分可 mock，但 mock 出来的不是「真实数据」 |

要把数字推到 100%，只有两条路，都不该做：
1. **改口径**：把不可达路径从分母里删掉 —— 这是凑数，不是覆盖率。
2. **伪造真实**：用大量 mock 冒充 GUI/Arbiter 交互 —— 违反用户「尽量用真实数据」与「真相优先」纪律。

**结论：72.54% 是当前约束下用真实数据能达到的诚实上限**。若用户愿意接受「真实 GUI + Arbiter」由自己在终端跑 900 局 E2E，那部分路径可由 `MSW_E2E_PROBE=1` 的真实遥测覆盖，届时再复测。
