## 〇、阅读约定与可信度分级

### 0.1 口径标记

| 标记 | 含义 |
|---|---|
| **【有效】** | 现行仍成立的结论，有受控验证（对拍 / 阴性对照 / 预注册判据 / 大样本 CI）支撑，且未被后续实验推翻 |
| **【有条件】** | 结论成立但适用范围严格受限（样本口径、配置、规则、局面复杂度），越界即不成立 |
| **【作废】** | 已被后续实测或复核明确推翻的旧读数 / 旧结论，禁止再引用 |
| **【未验证】** | 已提出或已建台架但未跑完 / 未达门线 / 未完成独立复现，不能作为结论 |
| **【口径隔离】** | 数字本身有效，但**只能在其自身配置下使用**，与别的配置混用即产生错误结论 |

### 0.2 贯穿全项目的方法学纪律（由 16 次返工提炼，来源：全局记忆 2026-11-03）

1. 先验证仪器，再测量（受控已知答案用例 + 阳性/阴性对照 + hook 核实参数真到达被扫路径）。
2. 区分「未观察到」与「不可能」：样本最大值不能证明上界。
3. 改/评生产代码前先读生产代码，不从 bench 行为反推生产缺陷。
4. 对照组必须是真对照（同 seed 配对、同预算）；自选择分组不能相减。
5. 一次只改一个变量；删他人代码前必须有能区分「原代码错」与「我的测试错」的判定。
6. 归因必须带证据，不把合理推测写成结论。
7. 每条结论标注证据边界（样本量 / 口径 / 未验证项）。
8. 发现集与验证集绝不合并出结论；合并值只能作探索性描述并标注含选择偏差。
9. 测量探针须做「归属自检」：逐样本核对「我以为的因」与「实际观察到的果」一致，系统性不一致优先改探针归属而非加样本。

## 一、总览：项目目标与实验主线

**原始目标**：通过优化算法，使胜率达到 **40% 以上**（后续一度扩展为 50% 可行性研究）。

实验主线按时间形成五个阶段：

| 阶段 | 时间 | 主问题 | 净结果 |
|---|---|---|---|
| Ⅰ 基线建立 | 2026-09-02 ~ 11-02 | 耗时模型、Arbiter 规则逆向、纯规则基线 | 规则与仪器地基确立 |
| Ⅱ 性能与正确性修复 | 2026-11-02 ~ 11-03 | 10x 提速、概率正确性、内存防爆 | 决策 387→79.8ms；修复 4 个 P0；2000 局零累积 |
| Ⅲ 胜率 50% 可行性与 2000 局基线 | 2026-11-03 ~ 11-04 | 规则效应、首点质量、残局、2000 局胜率 | +16pp 规则差；35.45% 基线；残局读数多轮作废 |
| Ⅳ 40% 攻关与权重线证否 | 2026-11-04 ~ 11-05 | 预注册 A/B、F 矩阵、LP 证否、C++ 桥接 | 40% 未达成；权重调参被数学证否；桥接顶爆内存 |
| Ⅴ 统一 decide 与 17.9 万局收口 | 2026-11-06 ~ 11-07 | 纯 C++ decide 循环、生产链路整改 | **39.85% ±0.23pp**（17.9 万局），处于 40% 边缘 |

**一句话总结**：算法侧能稳定拿到的离线胜率约为 **39.85%（纯 C++ decide 循环口径，17.9 万局）**，距 40% 目标差 0.15pp 且 CI 跨线；绝大多数「提升 X pp」的候选方案都因样本量、自选择偏差、仪器缺陷或数学证否而未能成立；项目最大的实际收获是**一套被反复验证的测量纪律**和**大量明确的否定性结论**。

## 二、阶段 Ⅰ：地基（2026-09-02 ~ 11-02）

### 2.1 耗时模型与预算控制（2026-09-02 ~ 09-03）【有效 / 有条件】

- 实验：`utils/probability.py` 记录每次 `part_solve` 实测耗时到 `data_time.json`，拟合 `t(L)=base·k^(L-33)`；`bench/profile_fitk.py`、`bench/compare_wr.py`、`bench/bench_wr_speed.py` 等。
- 结论：`k` 由 `_ps_fit_k` 自动拟合（大组 size≥30 样本配对比值中位数，夹限 [1.05,2.0]，窗口最近 200 条），`predict/observe` 统一读 `state['ps_k']`，真实 `k≈1.08–1.11`（C++ 版增长平缓）。状态持久化在 `state/time_budget.json`。
- **【有条件】**：`k` 是本机 / 本二进制 / 本负载下的**在线预算启发式**，不是普遍算法复杂度常数；缺时间外验证、预测区间与负载分层，不可跨机器外推（审计 P1-5）。
- 修复记录：`_ps_refit_k` 未按注释截窗（全量 O(n²)）→ 加 `_PS_FIT_WINDOW=200`，1777 条样本拟合 25.5ms→1.66ms（15.4x）；`_ps_observe` 39.8→19.8ms。样本文件加 `_PS_SAMPLES_KEEP=1200` 滑窗上限。

### 2.2 Arbiter 0.52.3 雷生成算法逆向（2026-11-02）【有效】

- 方法：REA 脱壳（UPX；493,056→1,944,576 字节，18→5305 函数）、Ghidra 反编译、`tools/arbiter_generation_truth.py` 8/8 证据链自检。
- 结论：**纯拒绝采样布雷**，`Random(n) = (uint64)n * RandSeed >> 32`，LCG `RandSeed = RandSeed*0x08088405 + 1`（全代码段仅 1 处，VA 0x4033d1），种子来自 `CryptGenRandom`。布雷函数 `0x4d9228` 函数体内引用宽/高/棋盘、**雷数引用 0 处**（由 EAX 传入），6 个调用点全在 `0x5313b8` 的不同分支。
- **首点安全机制**：先点开（含 flood-fill）→ 再布雷 → 拒绝采样只跳过已开格 ⇒ **只保证首点本格安全，不保证 3×3**。
- 勘误留痕：早期曾误以为「首点 3×3 排除与 Arbiter 行为等价」「安全区通常更大」，**已被 11-03 修正推翻【作废】**（见 3.3）。

### 2.3 纯规则随机基线（2026-11-02，2000 局，seed=20261102）【有条件】

| 策略 | 胜率 | 95% CI | 平均踩雷步数 |
|---|---:|---|---:|
| B1 纯瞎猜 | 0/2000 = **0.000%** | [0.00%, 0.19%] | 4.3 |
| B2 纯推理 + 瞎猜 | 15/2000 = **0.750%** | [0.46%, 1.23%] | 64.1 |

- **【有条件】**：这两个数是在**旧模拟器（首点 3×3 排除）**下跑的，开局已知区域虚高约 5.3 倍；因 B1 恒为 0、B2 绝对值极小，作为「无智能下限」的**定性结论**仍成立，**精确数值应在修正后模拟器上重跑（未重跑）**。
- 对照：项目真实对局 33.86%（107/316，`state/game_stats.json`）。约 45 倍差距全部来自「猜得更准」（概率枚举 + 胜率搜索）——这是算法改进唯一有价值的方向。

## 三、阶段 Ⅱ：性能与正确性修复（2026-11-02 ~ 11-03）

### 3.1 视觉矢量化与单步耗时（2026-11-02）【有效 / 有条件】

| 指标 | 修复前 | 修复后 | 倍数 |
|---|---:|---:|---:|
| 单次决策 `number5_1` | 387.1 ms | **79.8 ms** | 4.8x |
| 视觉全盘识别 | 309.6 ms | **48.0 ms** | 6.5x |
| 单格识别 | 0.645 ms | 0.100 ms | 6.5x |
| `_ps_refit_k` | 49.2 ms | 4.6~5.6 ms | ~10x |
| `_ps_observe` | 39.8 ms | 15.8~19.8 ms | 2.5x |

- 方法：480 格 × 25 模板 = 12000 次 `cv.matchTemplate` → numpy 批量同语义计分；9 组测试逐格 0/480 不一致；40 张随机棋盘 0 分歧；变异体测试证明测试能检出缺陷。
- **结论【有效】**：单步墙钟 487ms 里视觉 309.6ms（63%）、决策 78.4ms、点击后固定 `sleep(0.1)` 100ms；C++ `part_solve` 仅 2.3ms、`win_rate` 常 0ms ⇒ **「算法侧 10x」拿不到，瓶颈在视觉与等待**。
- **【有条件】**：所有识别准确率结论仅在**合成棋盘**上成立；仓库内**没有任何真实截图 + 标注集**，真实 DPI / 主题 / 缩放 / 半透明叠加泛化未验证（审计 P1-6）。
- 被推翻的仪表结论【作废】：cProfile 曾显示 `_ps_refit_k` 占 60%（52 万次调用），墙钟插桩复测推翻（真实 10.3%）——**对该项目 cProfile 会误导热路径判断**。

### 3.4 2000 局内存爆炸与 node_cap 防护（2026-11-03）【有效】

- 用户实测 2000 局消耗 20+GB 被顶爆。定位 4 个独立根因，全部修复后（25 局）单局峰值 65.8MB、跨局趋势 +0.032MB/局、外推 2000 局约 112MB，生产算法未变（数值对拍 11/11 逐位一致）：
  1. `bench/ab_policy.py` monkey-patch 闭包链跨局累积（2000 局 = 2000 个 Solver+Board 常驻）→ 模块级快照 + `finally` 还原 + 断引用。
  2. `bench/compare_2ply_vs_winrate.py` 世界用 `set[tuple]`（每世界约 4KB，n=114,870 时构造阶段 497.6MB）→ 位集整数（480bit≈100B），构造 ΔRSS 497.6→25.1MB。
  3. 世界数上限检查在分配之后 → 新增纯算术 `count_worlds_exact()` + `WORLD_CAP_DEFAULT=200000`，分配前拦（1.45 亿世界局面拦截时峰值 1KB）。
  4. 非法局面（实测 `F=8,U=471,num10=0,a=99`，世界数 10^148 量级）→ 前置合法性校验 `0≤num10≤a`、`U≤w*h`、`U≤60`。
- 生产 `win_rate` 节点数硬上限 `node_cap=2e6`（C++ 抛 `node cap exceeded` → Python 按消息子串识别 → 降级贪心；**不回退纯 Python、不落外层 except**）。标定：每节点中位 15.2B / 最大 21.2B，`2e6×25B≈48MB`，对 1.5GB 预算留约 30x 余量；实测本机最大节点需求 424,114，默认下零触发是**正确**的（不能用「本机是否触发」反推 cap）。
- **否证【有效】**：位集重构把每世界内存 2304B→64B（36x），但总内存 19.2→19.1MB 几乎不变（memo 节点开销主导）⇒ 位集不作为防爆手段。
- 方法教训：必须用真实 RSS 而非 `tracemalloc`；必须区分「单局峰值」与「跨局累积」；上限检查必须在分配之前；非法局面先于性能优化处理。
- 验收：`verify_world_cap.py` 7/0、`verify_mem_safety.py` 3/0、`oracle_bruteforce.py` 不一致 0、`verify_world_enum.py` 11/11、`verify_node_cap*.py` 30 项断言全绿。

### 3.6 win_rate 加速 14.12x（2026-11-03）【有条件】

- 33 个生产真实决策点微基准：总耗时 4652.15→329.49ms（**14.12x**），全部用例输出指纹逐位一致；最重用例 #13（42.4 万节点）2246→212ms（10.6x）。端到端 12 局胜率 33.33%、零错误零降级。
- 方案演进：A 无分配 128 位哈希 4.66x → B「可加哈希」第一版用了不可逆 xor-shift（**错误已修正**）→ 最终纯可加 128 位增量哈希 → Board 打包化（4 位/格）。
- **【有条件 / 口径隔离】**：14.12x 是**加总口径**；同一份数据逐用例比值中位 8.76x、中位耗时比 5.97x，且 case13 独占 before 总时长 48.3%（剔除后逐用例中位 20.49x）。整局加速约 1.28x，远小于微基准。**「目标 10x 已达成」依赖最有利的加总口径**（审计 P1-5）。
- **【作废】**：后续发现同进程内连续调 `win_rate` 耗时漂移（G10 5.44x、G11 2.36x，新进程极差 2.1%，根因未明）⇒ 任何**同进程内耗时对比不得用于策略排序**；强制定 `bench/timing_protocol.py`（新进程 / 随机交替，极差 >20% 标 unreliable）。14.12x 在按新协议复测并补 returncode / 用例集合硬门前，不作为可复现性能结论引用。

### 5.7 ⭐ 数学证否：线性权重调参不可分离【有效 / 有条件】

- 方法：把「是否存在权重使每点都选对」转成线性不等式组，用 **HiGHS LP 精确判定**（可判定性证明，非采样搜索）。

## 八、目标达成情况与最终结论

### 8.1 40% 目标

| 口径 | 读数 | 判定 |
|---|---|---|
| P2 正式 corner（2000 局） | 39.60%，CI [37.48,41.76] | 未达标（点估计 <40%、CI 跨线） |
| P2 复现 corner（2000 局） | 37.25%，CI [35.16,39.39] | 未达标（CI 全在 40% 以下） |
| **纯 C++ decide 循环（178,690 局）** | **39.85%，CI [39.62,40.08]** | **未严格达标**（差 0.15pp，CI 上界刚过线）：处于 40% 边缘 |

**结论**：**40% 目标在 Arbiter 规则下未严格达成**，但 17.9 万局大样本把点估计收敛到 39.85%±0.23pp，是项目至今最可靠的算法上限读数。该读数属于「纯 decide 循环」口径，**生产 GUI 自动模式尚未验证吃到**（同 seed 对拍约 20% vs 40%）——这是从「算法上限」到「用户可感知价值」之间尚未闭合的一环。

### 8.2 50% 可行性

**未判定**。Arbiter 33.50%（n=600）、现代规则 49.50%（n=600，CI 未排除 <50%）；+16pp 只是本算法在该协议下的实测效应，不是理论上限；残局无偏测量与「Arbiter 下独立 seeds 算法 A/B」两项前置未完成。**50% 按哪个口径验收**仍是需要用户裁定的开放问题。

### 8.3 最可靠的五条净结论

1. **规则地基**：Arbiter 延迟布雷、首点只保本格；它使角落开局在机制上优于中心（首格为 0 率 49.85% vs 15.45%），这是本项目一切胜率实验的前提。
2. **算法骨架正确**：`win_rate = safety × 后续胜率 ≤ safety` 使现有剪枝成为最紧分支定界；2-ply、删剪枝、补全记忆化键等「优化」均被实测否证；单/双格推理已被全枚举覆盖。
3. **胜率读数**：最可靠的是 **39.85% ±0.23pp（17.9 万局纯 decide 循环）**；35.45%（2000 局）、36.35%（P2 center）、33.50%（rule_gap）各有独立口径，不可混用；真机约 34%。
4. **调参路线被数学封死**：7 维线性指标 LP 不可分离、扩到 12 维与分层 25 桶仍不可分离、收益上限 0.002666 < LOO 方差 0.005251（浅局面 worlds≤2016）。继续调权重不可能产出可信收益。
5. **测量纪律是最大资产**：项目用受控反例、注入必红、独立枚举、接线回读、原子事件捕获、按局聚类、预注册冻结判据、发现/验证集隔离，累计推翻并作废了至少 16 类错误读数（详见第九节）。**「未检出」≠「不存在」，「不显著」≠「无效」，「微基准」≠「端到端」** 是贯穿全报告的口径底线。
