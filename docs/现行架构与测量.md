## 一、决策链路（唯一路径）

```
GUI / Solver.play 或 help
  │
  ├─ utils/vision.py      真实屏幕抓图（窗口矩形 BitBlt / 整屏回退）
  │                       模板匹配 → cell_value (h+2, w+2 int32)
  │                       编码：0-8 已开数字 / 9 未开 / 10 标记雷
  │                             / 11 推理安全 / -1 UNKNOWN
  │
  ├─ utils/probability.py
  │     validate_board_consistency(cell_value, a, w, h)   ← decide 之前
  │     number5_1(cell_value) → _number5_1_core
  │
  └─ utils/native.py → native.decide(cell_value, a, w, h, node_cap, is_play)
        │
        └─ cpp/mscore.cpp → py_decide → decide_impl
              │
              ├─ count_situations_exact()   精确 ‖S‖ = 完整一致世界总数
              │                             （AAAI-17 WS-17-15 Algorithm 1）
              │
              ├─ ‖S‖ ≤ criterion  →  OPTIMAL(...)          Algorithm 3 line 2
              │     criterion = DSTAR：自动 256 / 帮助 768（×3）
              │     MSW_DSTAR 可覆盖；世界数物化受 MID-LOOP GUARD 限制
              │
              └─ 否则          →  pbs + PSEQ（启发式）    Algorithm 3 line 4
                    内存闸门 1.5GB（用户铁律，不可调）
                    COST_CAP / node_cap 限制精确引擎规模
```

### 1.1 关键常量与开关

| 项 | 值 | 位置 |
|---|---|---|
| `DSTAR_AUTO` | 256（论文 PSEQ-D256 的 criterion） | [cpp/mscore.cpp](../cpp/mscore.cpp) `decide_impl` |
| 帮助模式 DSTAR | `DSTAR_AUTO × 3` = 768 | 同上 |
| `MSW_DSTAR` | 覆盖自动模式 criterion | 环境变量 |
| `DEFAULT_MEM_BUDGET` | `1536 × 1024²` = 1.5GB | C++ 决策层，**不可调** |
| `node_cap` | 默认 2,000,000；`native.decide(..., node_cap=...)` 可覆盖 | `py_decide` 导出 |
| `HELP_TRANSITION_WORLD_CAP` | 200,000 世界 | C++ 帮助态转移 |
| `DECISION_TIME_BUDGET` | 30.0s | [utils/probability.py](../utils/probability.py) |
| `coarse_cap` | `DSTAR × 4` | 廉价粗筛（`‖S‖ ≥ world_upper` 方向安全） |

### 1.2 返回值与诊断

`decide` 返回 dict：`x, y, confidence, path, reason, prob, tied, weighted`，
以及诊断字段 `situations`（精确 ‖S‖）、`dstar`、`limitation`（仅诊断，
不参与决策）、`world_upper`、`mem.*`。

`reason` 取值：`certain_safe` / `optimal` / `memory_gate` / `clicks9_fallback` /
`limitation` / `no_frontier`。两轮真机 E2E 的 reason 分布逐项差 <0.25pp，
算法行为一致（见 [分析结论-第二轮201局.md](../state/e2e_900/分析结论-第二轮201局.md)）。

` ‖S‖ 哨兵语义：`-1` = 未计数；`DSTAR+1`（257）= 精确计数超限时返回的
`cap+1` 哨兵，**不是真实世界数**。分析器必须把三者分开，否则会得出
「‖S‖ 中位 257」的假读数。

### 1.3 已删除的东西（不要再找）

- `wr_threshold`：C++ 形参已删；`utils/native.py` 仅为兼容旧调用方保留同名形参，
  **不转发、不生效**。
- `win_rate` / `part_solve` / `part_solve_single` / `pbs_compute`：
  Python 生产侧已删；pyd 仍导出后四个（供历史 bench 用），生产零调用。
  精确 V* 引擎的 `exact_eval` 导出**已从 pyd 删除**。
- LAYER 2 自适应前瞻、`limitation ≤ wr_threshold` 准入、`_wr_*` 系列函数、
  `MSW_WR_NODE_CAP`、`MSW_NATIVE_TUNE`、`LIMIT_BONUS_*` 自适应阈值链：全删。
- Python 决策回退链：删。决策不可用时统一
  「ERROR 日志 + 用户可见警告 + 全盘安全重扫 + 不点击」。
- `MSW_DISABLE_NATIVE=1` 仍会禁用 pyd 加载，但**不再能自动扫雷**
  （因为已无第二套决策实现）。

### 1.4 真实盘面校验（用户硬要求）

`validate_board_consistency(cell_value, a, w, h)` 在每次 C++ `decide` 之前
对**已经扫出来的真实盘面**做逻辑一致性检查；不通过则重扫、不把脏盘面
喂给 C++。「直接扫描真实盘面、用真实盘面数据 debug」是硬约束，不要用
合成盘面代替真机验证。

## 二、状态转移预览（仅帮助页）

- 数据：`native.transitions_for(cv, a, w, h, x, y)`，复用本次 `decide` 缓存的
  世界集，按 `click_outcomes` 分组。

- 一行一个分支（纵向列表）；中局/残局超过 `HELP_TRANSITION_WORLD_CAP=200000`
  时**不计算转移、不合成概率**，只显示准确原因 `world_count_exceeded`。
- 事实层读真实 `cell_value`；一致世界只用于推断**新打开格**。
- **Auto 界面不接状态转移预览**，只显示热力图。

## 三、主循环、局末与终止

### 3.1 自动模式

`utils/solver.py` 的 `AutoPlayThread`：

- `play()` 每轮：探测胜负/弹窗 → `complete_scan` → `number5_1`（decide 循环）
  → 点击（`certain_safe` 可批量）→ `rescan_after_click` → 循环。
- 统计：`won` 时 `win += 1`，总是 `total += 1`，然后 `_gs_save(total, win)`
  与 `probe.game_end(...)`（口径已统一）。
- 局末重开 `_restart_after_game` 为**事件驱动**：
  1. 等弹窗消失（窗口内模板匹配 / 标题窗口）
  2. 点 OK / 笑脸 dismiss
  3. 等棋盘像素签名变化（`game_end.reset` 的 `ok` 字段）
  4. 点首点（`game_end.first_click` 的 `ok` 字段）
  `MSW_LEGACY_SLEEP=1` 回退到旧固定 sleep 链 `[1.2, 1.0, 0.5, 0.1]` 做对照。
- 弹窗模板匹配改在 **Arbiter 窗口矩形内**（`_dialog_templates` 一次区域抓图
  + 批量模板匹配）；`locate_exit` 在窗口内 `_min > 0.05` 时整屏回退。
  区域抓图用**屏幕 DC** BitBlt（`win32gui.GetDC(0)`），否则独立顶层弹窗会漏。

### 3.2 终止（用户铁律：鼠标动起来后仍能停）

- 全局热键：Win32 `GetAsyncKeyState` 轮询物理键，不需要焦点、不需要鼠标。
  - 默认 `ESC (0x1B)`；`MSW_STOP_HOTKEY=0x7B` 改 F12；`=0` 关闭。
  - `AutoPlayThread.start()` 起守护线程，`run()` 的 finally 停掉。
- `request_cancel()` 与 GUI 停止按钮共用同一协作式取消通道；decide 循环与
  `certain_safe` 批量点击循环内都有取消检查。
- `pyautogui.FAILSAFE`：GUI 手动跑时保留；`bench/e2e_900.py` 自动化 runner
  里显式置 `False`（鼠标会被程序拖到角落）。

### 3.3 DPI 事实

必须先 `import pyautogui` 再调 `win32gui.GetWindowRect`：否则拿到逻辑坐标
（510×400），DPI-aware 下才是物理坐标（本机 765×600）。
[cfg.json](../cfg.json) 的 `bx/by/cell_width` 按物理像素标定。

### 4.3 分析器的已知口径陷阱（必须遵守）

1. **真实墙钟** = 主跑段首个 `game_begin` → 最后一个 `game_end` 的 ts 跨度
   除以 `game_stats.json` 累计差；`game_end.wall_ms` 中位（0.46s）只覆盖
   上一局最后一轮决策，**不是单局时长**。
2. **跨轮切段**：`probe.jsonl` 追加写、重跑不清空；按 >60s 空档切段，
   且 `summary.json` 必须按本次进程 `t_run_start` 过滤 + 用 `game_stats`
   累计差交叉校验。旧 `summary.json` 的「257 局/100 胜/38.91%」是两轮混算，
   **已删除**。
3. **嵌套 span 不可相加**：外层 `play.*` 含内层 `click/vision/ui/decision`，
   两层相加会得到 >100% 的假占比；归因只取一层（内层）。
4. **`situations` 三态**：`-1` 未计数 / `DSTAR+1` 超限哨兵 / 真实 ‖S‖，
   必须分开统计。
5. **内存泄漏**判据用逐局峰值段的 `drop_pct`、净增与回落占比三条同时成立；
   单点峰值/5 段段末单调都会误报。上轮结论：commit 824→932MB、峰 1326MB、
   13.1% 采样点有回落 ⇒ **非泄漏**。
6. **A/B 等效**不能看总数相同：调阈值/触发门类必须同 seed 配对 McNemar；
   独立两臂胜率相减无效。
7. **先验证仪器再信读数**：两个差异很大的条件给出完全相同结果，先怀疑读了
   常量/累计值。

### 4.6 真实盘面黄金测试与 decide 确定性（2026-11-10）

用 `bench/data/midgame_cases.json` 的 **400 个真实中局盘面**（18×32 =
30×16+padding，带 `cell_value`/`a`/`clicks`/`clicks9`/`num10`）做黄金测试：
[tests/test_real_boards_golden.py](../tests/test_real_boards_golden.py)，8 项测试覆盖
`certain_safe` / `optimal` / `pbs(PSEQ)` / `clicks9_fallback` / `memory_gate` 分支。

**抓出并修复一个 P0 缺陷**：同一真实盘面连续调 `decide`，60 个里有 **12 个返回不同坐标**
（`(15,8)` ↔ `(15,10)` ↔ `(17,8)` 等）。根因是 PSEQ 残余平局用 `thread_local`
xorshift 随机数（`cpp/mscore.cpp` 原 L2636-2649），状态跨调用累积——与
`py_decide` 注释「tie-break is deterministic」**直接矛盾**，会让同 seed 复现、
A/B 对照、黄金基线全部失效。

修复：残余平局改用已有的 `deterministic_tie_break`（按 `(x,y)` 字典序最小值，纯函数）。
重编译后实测 **12/60 → 0/60 非确定性**，reason 分布逐项不变（证明只改平局打破、
未改决策语义）。回归测试锁住该性质，`test_decide_is_deterministic_on_real_boards`
在修复前 RED、修复后 GREEN。

> 注：本次重编译了 `utils/mscore.cp310-win_amd64.pyd`（当时无程序运行、pyd 未锁定），
> 旧版备份为 `utils/mscore.cp310-win_amd64.pyd.bak_before_determinism`。

### pyd 导出（2026-11-10 精简后，实测 3 个）

```
decide / transitions_for / split_frontier
```

- `decide`：唯一决策入口（OPTIMAL / pbs+PSEQ 两层）
- `transitions_for`：帮助页 7×7 状态转移（复用 decide 缓存）
- `split_frontier`：前沿/内部格切分（decide 内部 + decide_trace 诊断）

**已删除的 7 个导出**（Python 侧零调用）：`estimate_mem` /
