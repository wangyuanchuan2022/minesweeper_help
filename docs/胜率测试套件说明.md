## 一、怎么跑（历史描述，现已不可运行）

```
双击  run_winrate_suite.cmd        （该文件已于 2026-11-09 删除）
```

- 全程约 **4–5 小时**（本机 32 核 / 32 GB）
- 每个阶段写独立日志到 `state\suite\<时间戳>\`（该目录已于 2026-11-09 清理）
- 结果 JSON 写入 `state\ab\runs\<时间戳>\`，**永不覆盖历史**
- **S0/S1/S2 是硬门线：任一失败立即停止**，不浪费后面几小时
- S3–S7 是独立实验：单个失败不阻断其他
- 自动记录 git 版本 + 关键文件指纹（`manifest.json`）

> **踩过并修好的三个坑**（都靠"实跑"而非"看代码"发现）：
> 1. 干跑脚本放 `bench\` 下 ⇒ `%~dp0` 指向 `bench\` ⇒ 所有 `bench\x.py`
>    变成 `bench\bench\x.py`，**全部阶段 exit=2**。
> 2. 用 `wmic` 取时间戳 ⇒ **本机无 wmic** ⇒ STAMP 为空 ⇒ 目录名非法 ⇒
>    mkdir 静默失败 ⇒ **阶段打印 ok 却零日志、退出码仍是 0（假绿）**。

> 教训：**"逐个脚本冒烟通过"不等于"启动器可用"**，必须实跑整条链路。

## 二、阶段清单

### 硬门线（失败即停）

#### S0　脚本冒烟（~1 分钟）
- **脚本**：`bench/smoke_all_checks.py`
- **测什么**：16 个相关脚本能否用最小参数跑通、有实质输出
- **产物**：`S0_smoke.log`
- **要看的**：`通过 N 输出偏少 M 失败 K`，失败必须为 0

#### S1　仪器自检（~2 分钟）

| 子项 | 脚本 | 测什么 |
|---|---|---|
| S1a | `verify_first_click_wiring.py` | 首点坐标真的被采纳？开局分布符合理论？ |
| S1b | `verify_flood_chain.py` | flood 0 连锁正确性（含注入必红） |
| S1c | `verify_probe_chain.py` | 探针链路（外框隔离/坐标/残留检测） |
| S1d | `verify_endgame_safety.py` | 残局 `pending` 与 `prob_map` 配对错位 |
| S1e | `verify_expand_score_degenerate.py` | `expand_score` 是否在平局集内退化 |
| S1f | `verify_first_click_wiring.py`（重复确认） | 同上 |

- **要看的**：每个都为 `✔`；**有 ✘ 则后续读数不可信，必须停**

#### S2　台架确定性（~6 分钟）

| 子项 | 脚本 | 测什么 |
|---|---|---|
| S2a | `verify_seed_determinism.py --games 60` | 同 seed 是否唯一确定一局（棋盘哈希） |
| S2b | `verify_workers_determinism.py --games 60` | workers 1/4/20 结果是否一致 |

- **要看的**：`棋盘哈希可复现率` 必须 **N/N**；workers 逐局一致性 **N/N**
  - 否则**所有"同 seed 配对"读数失效**

## 四、读结果的四条纪律

1. **先看 S0–S2**。门线有问题时 S3–S7 的数字全部不可信（套件会自动停）。
2. **区分「未检出」与「不存在」**。看每个阶段报的 **MDE**（最小可检效应）：
   小于 MDE 的效应本来就测不出。S4 的 z 不显著、S6 的 CI 含 0，
   都只说明"当前样本测不出"。
3. **残局（S5）是最大未知**。在它出来之前，任何"算法已接近上限"
   "算法还能补多少"的判断都缺乏依据。
4. **区分发现集与验证集**。S6 是发现集（多臂挑选，含选择偏差），
   **只有 S6b 的独立 seeds 结果是主验证**。不要把两者合并当"接近确认"。
