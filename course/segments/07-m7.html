m6 结束时，未开格已按「是否贴着数字格」分成边缘 clicks 与腹地 clicks9，边缘又被切成互不共享数字格的组，算完的方案表进 checked 缓存。这一模块钻进其中一组的内部：number5_1 在 L190 把一组边缘格连同它的数字格集合交给 part_solve，回答一个组合问题——这组未开格里，雷怎么摆，才能让每个相邻数字格都满意？

答案的原始形状是 2 的幂：3 个未开格有 2³=8 种摆法，10 个就是 1024 种，20 个超过一百万种。part_solve 的做法是逐格试「是雷 / 不是雷」的二叉树，每放一格就检查一次约束余量，注定走不通的半棵子树当场砍掉——走迷宫时留绳，走不通就收绳回头：每前进一格放一段绳，撞墙就收回这一段，回到上一个岔口换条路再放。

    def part_solve(self, clicks, cell_value, num10, num9, cs, _try=False):
        """
        根据点击的坐标，计算出可能的值
        :param _try:
        :param clicks: 点击的坐标
        :param cell_value: 格子中的值
        :param num10: 10的个数
        :param num9: 9的个数
        :param cs: 雷的坐标
        :return: 可能的值
        """
        _cs = defaultdict(list)
        for i, j in clicks:
            for u in range(i - 1, i + 2):
                for v in range(j - 1, j + 2):
                    if 1 <= cell_value[v, u] <= 8:
                        _cs[(i, j)].append((u, v))
        _cs = dict(_cs)

        clicks = list(clicks)
        logger.debug("part_solve 待枚举格子数: %s", len(clicks))

def A(ck: list):
    """
    全排列
    :param ck: 列表中每一项长度
    :return: 索引组成的列表

    Examples
    --------
    >>> for i in A([2,1,3]):
    ...     print(i)
    [0 0 0]
    [0 0 1]
    [0 0 2]
    [1 0 0]
    [1 0 1]
    [1 0 2]
    """
    num = np.zeros(len(ck), dtype=np.int32)
    while True:
        yield num.copy()
        if len(ck) == 0:
            break
        num[-1] += 1
        for i in range(len(ck)):
            i *= -1
            if num[i] >= ck[i]:
                num[i - 1] += 1
        if num[0] >= ck[0]:
            break

        for i in range(len(ck)):
            if num[i] >= ck[i]:
                num[i] = 0
A 是跨组拼接的入场券：ck 是「每组的方案数」列表（number5_1 L162-L177 一边算一边攒），A(ck) 依次吐出所有「每组各选一个方案」的索引组合——名字写的是全排列，干的其实是笛卡尔积（名不副实，和 m2 的 ClientToScreen 一个传统）。docstring 的例子：A([2,1,3]) 吐 2×1×3=6 组索引。
实现是一只里程表：末位 +1，越界就向前进位，首位越界即枚举完毕，进位后归零。m8 里两个消费者都靠它：win_rate（L626）和 process_bigger_situation 的 else 分支（L438）——把各组的方案表拼成整条边界的假设局面。
