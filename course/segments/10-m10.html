10 · 自动模式：无人值守的一局

m9 的帮助模式每步棋都要用户按一次「帮助」；自动模式把整局、甚至连续几十局都交给程序自己跑。同一个 Solver、同一套推理引擎，从 run()（solver.py L131-L136）按 is_play 分流进 play(limit)——本模块讲这条主循环的完整生命周期：点击开局、胜负检测、扫描推理决策、无进展才进概率引擎，以及两个容易忽视的工程问题：信号节流与胜率记账。

入口的事件链：主界面点「自动」按钮触发 auto_play_func()（main.py L681），弹出对话框问总局数，minesweeper_run 启动游戏进程，然后 set_args(value) 把非零局数写进线程——is_play = value != 0（solver.py L45-L47）就此切换到自动驾驶舱。start() 之后主线程只剩两件事可做：盯进度条、等结束。

    def _throttled_pv_signal_emit(self, value):
        """节流发射pv_signal，每100ms最多发射一次，除非是特殊值(0或100)"""
        current_time = time.time()
        # 特殊值(0, 100)总是立即发射
        if value == 0 or value == 100 or value == -1:
            self.pv_signal.emit(value)
            self._last_pv_signal_time = current_time
            self._last_pv_signal_value = value
            return
        # 检查时间间隔
        if current_time - self._last_pv_signal_time >= self._pv_signal_throttle_interval:
            self.pv_signal.emit(value)
            self._last_pv_signal_time = current_time
            self._last_pv_signal_value = value
        # 否则跳过此次发射
进度条的取数口。概率引擎在枚举的每一层都会汇报进度（probability.py 有 10 处调用它），枚举密集时一秒能发几十次。节流阀的规矩：特殊值 0（清零）、100（打满）、-1 直通——进度条复位和收尾不能被节流掉，否则会停在半路。
普通值则看表：距上次发射不足 _pv_signal_throttle_interval（L90 定义为 0.1 秒，即 100ms）就直接丢弃这次发射——节水龙头，100 毫秒内只放一次水。进度条本来只给人看，人眼分辨不了高于每秒几十帧的更新，中间值丢了毫无损失。

为什么这样设计：QThread 里不能直接碰 GUI——Qt 的规矩是控件只能在主线程操作，跨线程更新轻则警告重则崩溃；信号与槽是唯一合法通道：工作线程 emit，主线程的槽函数安全更新（main.py L209 把 pv_signal 接到进度条 setValue）。但合法不等于免费——槽函数在主线程排队执行，pv_signal 的发射频率上不去节流就全压在 GUI 身上。100ms 节流（HANDOFF 文档 T1 记录的优化）就是在这条管道上加的阀门：进度照看、卡顿没有。

最后一件事：记账。概率引擎每次按置信度点击后，都把这一局的输赢记进 data.json 的对应桶里（probability.py L334-L349：confidence 乘 100 四舍五入作桶名，弹失败窗口记 lose、否则记 win），每攒 20 次点击落盘一次（L351-L354），急停时 finally 再兜底冲一遍。日积月累，这本账就能回答一个致命问题：引擎说的置信度，是真的吗？——天气预报员总说八成下雨，翻账本对一对就知道他诚不诚实。

📊 概率引擎诚实吗：标称置信度 vs 实际胜率

对账结果：七个桶的实际胜率全部贴着标称值——说 95% 的桶实际 93.9%，说 88% 的实际 87.8%，说 80% 的实际 80.2%，连最玄的 50% 桶都掷出了 51.3%。这本账的体量：data.json 共 48 桶、累计 13040 局（胜 11394 / 负 1646，整体胜率约 87.3%），数字来自 data.json 读取统计（2026-09-01 核算）。另一个常被引用的数字——README.md L7 声明「高级难度胜率 46%」——那是高级难度整局的口径，与本表按置信度分桶的校准口径不同，两者说的不是一回事，勿混用。若哪天 88% 桶的实际胜率显著偏离 88%，那就是概率引擎该修了——这正是这本账存在的意义。
