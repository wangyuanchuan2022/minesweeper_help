11 · 设置与校准：图纸描点对齐

m10 的自动模式跑挂了，十有八九不是推理不行，而是配置漂了——m2 的第一道测验题（换台电脑点击全偏几个像素）说的就是它。这一模块讲配置本身：cfg.json 这个「一切坐标换算的地基」长什么样、设置窗口 EditWindow 怎么用两次取点把 bx/by/cell_width 校准出来，以及校准里的两个工程细节：鼠标防抖与整数校验。

结构层定位：设置窗口 EditWindow（main.py L768 起）挂 6 个按钮各管一个字段——宽、高、雷数走数字输入框，游戏路径走文件对话框，limit 走带警告的输入框，唯独「校准」最特殊：不弹任何框，而是启动一条三步流水线（拉起游戏 → 两次取点 → 换算写回）。全模块就沿着这条流水线走。

全部家当就一行 JSON：棋盘几何（w/h/cell_width）、位置（bx/by）、游戏本体（path、win_name）、推理上限（limit）、进度条速度（speed）。两个魔鬼细节：其一，win_name 的值末尾带一个空格——FindWindow 按标题精确匹配，这个空格是游戏窗口标题的一部分，手滑删掉就再也找不到窗口（minesweeper_run 的 FindWindow，mm0.py L29）；其二，speed 是一个真实的小数（不是整数），说明「必须整数」从来不是 JSON 的限制。path 字段此处已脱敏。
校准的归宿：EditWindow 里所有改动都先写进 self.cfg 字典，点「确定」（accept）时整体 json.dump 落盘；关窗（closeEvent，L950-L951 同样 dump）也写，点「取消」（reject）不写。下次启动 Solver.__init__（solver.py L65-L66）读的就是这份新文件——校准一次，一直有效，直到你再次改它。

为什么这样设计：校准结果直接写回 cfg.json 而不是留在内存——重启、换会话都仍然生效，代价是任何一次误校准也会被持久化（好在下文的整数校验会在写回之前把坏数据拦下来）。反过来做「内存配置」则每次重启都要重新取点。这个方案的隐患在写回与加载都分散：加载散在 main.py 多处、utils/solver.py 的 __init__ 与 reload、setting.py 的 import 语句（cfg.json 缺失时 import 即崩）；写回也散在 accept 与 closeEvent 两处——HANDOFF 文档 2.4 节记录的 T3「统一配置管理」待办，冲的就是这个。

字段类别含义与出处

limit可调枚举复杂度上限（当前 80）；每 +1 计算时间翻倍——get_int_limit 弹窗文案的原话警告

现在看校准流水线本身。点「校准」按钮（get_int_bx，main.py L844）后发生三件事：程序先替你把游戏拉起来（minesweeper_run）；再启动一个 90×90 的放大镜窗口（MouseWindowTread，mm0.py L91 起）——它把光标周围 9×9 像素放大成 90×90、画上绿色十字线、永远贴着光标置顶显示，帮你看清像素级细节好对准格角；然后提示你把鼠标移到棋盘左上角并静止。怎么算「静止」？看下面两段代码。

        count = 0
        time.sleep(1.3)
        pci = ctypes.wintypes.POINT(0, 0)
        pci = ctypes.pointer(pci)
        ctypes.windll.user32.GetCursorPos(pci)
        o_x, o_y = (pci.contents.x, pci.contents.y)

            pci = ctypes.pointer(pci)

            n_x, n_y = (pci.contents.x, pci.contents.y)
            if n_x == o_x and n_y == o_y:
                count += 1
            else:
                count = 0
            if count >= 8:
                self.pos_signal.emit(tuple((n_x, n_y)))
                return
            o_x, o_y = n_x, n_y
第①次取点落袋：emit 过来的屏幕坐标先经 ScreenToClient 换算成窗口相对坐标存成 x0/y0（mm0.py L52-L59——和 m2 讲过的 ClientToScreen 一样是拿窗口矩形左上角当原点的「名不副实」实现）。存完立刻提示第二点，并把「设置」窗口提到前台，让你能看到提示文字。
防抖的全部机关在这 21 行（mm0.py L75-L88 的循环）：每 0.1s 读一次光标，位置只要动了，count 立即归零重来；连续 8 次纹丝不动（8 × 0.1s = 0.8 秒）才 emit 出去——程序认定你「指好了」。开头的 sleep(1.3) 只是给你挪鼠标的准备时间，不是防抖本身。

    def get_pos_2_func(self, pos):
        self.x1, self.y1 = pos
        hwnd = win32gui.FindWindow(None, setting.win_name)
        self.x1, self.y1 = ScreenToClient(hwnd, self.x1, self.y1)

        cell_width = (self.x1 - self.x0) / self.w
        self.cell_width = round(cell_width)
        if abs(self.cell_width - cell_width) >= 0.11:
            QMessageBox.about(self, "提示", "现在每个格子的宽度不是整数，请调整扫雷窗口大小。")

            self.mouse_window.terminate()
            del self.mouse_window
            self.mouse_window = None
            return
        self.bx, self.by = round(self.x0 - self.cell_width * 0.5), round(
            self.y0 - self.cell_width * 0.5
        )
        self.cfg["cell_width"] = self.cell_width
        self.cfg["bx"] = self.bx
        self.cfg["by"] = self.by

        self.label_bx.setText(str(self.bx))
        self.label_by.setText(str(self.by))

量出图纸的格子尺寸：第二点同样换算到窗口坐标，然后水平总距离 (x1−x0) 除以列数 w——对角线量的是棋盘总宽，除以 30 列得到每格的像素宽 q。round 取整，但 round 只是候选：下一行马上验货。
整数校验：取整前后的偏差 ≥ 0.11px 就拒绝——尺子刻度必须落在整数格上。这不是洁癖：坐标换算链全部按整数 cell_width 做乘法（m2 的换算链），偏差会逐列累积（q1 详谈）。拒绝 = 弹窗让你调整扫雷窗口大小、关掉放大镜线程、直接 return——注意此刻一个字都没写进 cfg，坏数据到不了磁盘。
半格回退 + 收尾：你指的左上角是「第一格左上角的格角」，而点击公式 bx + m×cell_width 要落在格子中心——所以原点要往左上退半格，bx/by 就是「虚拟第 0 格的中心」（几何图解见下）。三件套写回 self.cfg 等待落盘（见第一个翻译块），label 显示新值、按钮解锁、放大镜线程清理，校准完毕。

cfg.json 里存的 bx/by 是窗口相对坐标；每次启动自动模式，play() 都先用 ClientToScreen 按当时的窗口矩形把它换算成屏幕坐标（solver.py L158）——所以两次运行之间移动窗口不用重新校准，换分辨率 / 窗口边框尺寸变了才要。
