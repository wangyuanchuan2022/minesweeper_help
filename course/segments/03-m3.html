3 · 点击后增量重扫：多米诺倒下之后

自动模式里程序刚点开一格，扫雷的 flood-fill 可能瞬间翻开一大片——像推倒一张多米诺。下一轮推理需要最新的棋盘，全盘重识别太贵，于是这里有一条「像素指纹」快速通道：只对真正变了的格子重新认字。

    def rescan_after_click(self, cell_value):
        """点击后重扫：抓取新棋盘，只重新识别发生变化的未开格子。

        扫雷点击空白格会触发 flood-fill，实际打开的区域可能远大于 5×5，
        因此不能固定扫描 5×5 窗口，而是对「所有仍标记为未开(9)」的格子做变更检测，
        只对真正变化的格子重新做模板匹配。
        """
        old_img = self.img
        self._grab_board()
        for y in range(1, self.h + 1):
            for x in range(1, self.w + 1):
                if cell_value[y, x] == 9:
                    new_cell = self._slice_cell(self.img, x, y)
                    old_cell = (
                        self._slice_cell(old_img, x, y) if old_img is not None else None
                    )
                    if self._cell_changed(old_cell, new_cell):
                        cell_value[y, x] = self.compare_img(new_cell, no_10=True)
        return cell_value
docstring 把设计动机写得明明白白：flood-fill 翻开的区域不可预测，固定扫 5×5 会漏，全盘重扫太贵——所以「对所有 9 格做变更检测」是唯一既不漏又不贵的方案。这段文档是接手者读 vision.py 的第一站。
两张整盘图（旧 self.img、新抓的）都在内存里，逐格切片比对。注意谁调它：number0 和 number_3_1 在自动模式点击后立刻调用（deduction.py L103 / L239）——推理进行到一半，必须马上看到 flood-fill 送来的新数字，等下一轮主循环就晚了。
🎯 押一注：均值差 2.9 的「假未开」会去哪

flood-fill 实际翻开了某格，但浅色数字「1」和未开背景的像素太接近——新旧切片的均值差只有 2.9，低于阈值 3.0。先押一注：这格接下来会被怎么处理？

📄 真实代码 utils/vision.py · L149-L155 
    @staticmethod
    def _cell_changed(old_cell, new_cell, threshold=3.0):
        """比较新旧格子图像，判断是否发生变化（用于点击后只重扫变化区域）。"""
        if old_cell is None or old_cell.shape != new_cell.shape:
            return True
        diff = np.abs(old_cell.astype(np.int16) - new_cell.astype(np.int16))
        return float(diff.mean()) > threshold
像素指纹比对：两张切片逐像素做差、取绝对值、再求全图均值——一个标量概括「这格变没变」。先 astype(np.int16) 再相减是防 uint8 的无符号回绕（200 - 250 会绕成 206 而不是 -50）。阈值 3.0 意味着平均每个通道只动 3 个灰阶就算「变了」，抗轻微反光，但挡不住「浅色数字 vs 浅色背景」这种 2.9 的边界情形。

    def complete_scan(self, cell_value, no_10=True):
        pyautogui.moveTo(10, 640, _pause=False)
        self._grab_board()

        for y in range(1, self.h + 1):
            for x in range(1, self.w + 1):
                if cell_value[y, x] == 9:
                    cell_value[y, x] = self.compare_img(self.cell_screenshot(x, y), no_10)

        return cell_value
另一台扫描仪——全量版。三处细节值得停一停：①先把鼠标挪到 (10, 640) 且 _pause=False 不吃 0.01 秒节流——悬停高亮会改变格子外观，不挪走就干扰模板匹配；②只认 == 9 的格子，已识别成数字的格子不再重识别（上一节赌注里那个静默坑的另一半正来自这里）；③cell_screenshot 只是 _slice_cell 的薄封装（vision.py L114-L115），两条扫描路径用的是同一把切刀。

为什么这样设计：变更检测（切片均值差，纯 numpy 毫秒级）替模板匹配（每格 25 次 SQDIFF）当守门员——遍历全部 9 格做廉价检查，只把真变化的送进昂贵通道。兜底是三层：rescan 每轮跑、主循环 complete_scan 只认 9、连续 3 次识别矛盾就全盘重置。3.0 这个数不是推导出来的，是抗噪经验值——动它之前先想清楚赌注揭晓里那个静默陈旧坑。

🛤️ 把一次「需要新棋盘」的请求拖过调度岔口

两台扫描仪服务同一个沙盘，但触发时机完全不同。岔路口在推理层与主循环的交界：点击之后同步走增量，主循环每轮走全量。切换场景投放令牌，看请求分别落进哪台机器。
